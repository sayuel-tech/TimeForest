# UI、交互与代码复用分析

依据：2026-09-08 实际维护工作树，静态版本 6.3.21，包含上一轮资产整改。核对 AGENTS、代码地图、当前状态、公共组件规范及前后端调用方。本轮是代码与规范分析，不是新的功能修复；未启动生产服务、进行浏览器视觉验收或生成测试。

结论：项目已经有公共基础，尤其原三个视频模式共用较多。主要问题是图片、视频接续加入后，一部分公共能力只复用了底层，页面组合和交互细节仍各自实现。下一步应补齐公共组件覆盖和适配契约，保留已有工作流与业务差异，无需重构全站。

## 1. 可以复用的 UI 和 UX，以及实际状态

下表路径以 `static/studio/` 为根；设计样式变量在 `static/styles/tokens.css`。

| 可复用内容 | 当前公共入口与覆盖 | 适合共同维护什么 | 必须保留的业务差异 |
|---|---|---|---|
| 色彩、字体、圆角、间距 | tokens.css、styles/base.css、components.css、workbench.css 已共用 | 纸色、森林绿、标题/正文层级、按钮与卡片状态、响应式规则 | 独立模式的插画和工作内容；共用视觉语言不等于复用同一张插画 |
| 三栏工作台和属性页签 | ui/workbench.js 的 workbench/propertyTabs/bindWorkbench，五模式均有接入 | 目录/画布/属性区布局、页签选择、窄屏处理 | 图片画布工具、故事分镜、接续轨道及各步骤的属性页签内容 |
| 制作参数弹窗 | ui/production-settings.js、styles/production-settings.css，原三视频/图片/接续三类适配均调用 | 外壳、标题、分类导航、字段网格、关闭与焦点、操作栏顺序 | 参数定义、作用域、默认值、应用/保存含义；不能把视频参数搬进图片 |

| 导入来源与参考素材卡 | ui/reference-assets.js 已供视频和接续使用 | 本地/资产库同级入口、素材卡、用途/角色、管理入口 | 图片 A/B/遮罩、视频原片、音频用途和继承规则 |
| 错误反馈 | ui/error-feedback.js 在图片、接续、任务中心、回收站等使用；原三视频部分入口未使用 | 分类摘要、原始错误展开/复制、失败后保留草稿 | 错误来源与恢复动作；不能把所有错误都当成参数错误 |
| 候选与可恢复移除 | ui/candidate-records.js 服务图片与原三视频，接续仍手写候选动作 | 当前选用保护、移除/恢复说明、状态/动作布局 | 图片输出与运行的关系、视频逐段审核、接续选用后加入轨道 |
| 全局资产与任务管理 | 资产页、共用选择器、features/task-center、分类回收站已有统一入口 | 跨页面选取、收藏、使用记录、活动任务查看和按归属停止 | 不把全部历史塞进全局活动队列，不统一不同业务的删除保护 |

可复用 UX 不只是按钮外观，还包括：取消不产生保存副作用；应用修改对应草稿；保存成功才能继续后续操作；刷新不覆盖正在编辑的内容；重复点击不重复提交；异步结果不能写进已经关闭/切换的页面；移除保留可恢复记录。这些原则应共用，但目前执行这些原则的代码仍有分散。

## 3. 应该进一步复用、目前仍重复或覆盖不足的部分

优先级表示实施顺序，不代表已复现的线上故障等级。下列源码行号对应本次审查快照。

### 第一批：直接减少界面漂移和交互不一致

**A. 项目页头与步骤导航：同一视觉组合有三套模板。**

- 原三视频：`static/studio/app/workspace-controller.js:218`。
- 图片：`static/studio/features/image-results/workspace-view.js:125`。
- 接续：`static/studio/modes/video-assembly/workspace.js:87`。

目前共用 class 和制作参数按钮，但标题、摘要、状态、步骤 HTML 仍分别拼接。建议提供公共 projectHeader 和 stepNavigation，模式只传名称、摘要、状态、步骤定义、当前步和事件。不能统一步骤数量，也不能让导航自动越过各模式的保存门。

**B. 错误反馈：已有组件，旧视频入口仍绕开。**

`app/workspace-controller.js:112、218` 和 `features/production/review-parts.js:7` 仍使用普通 notice/error 文本；图片与接续使用分类、展开、复制原始错误的 errorFeedback。后端 image_studio/routes、video_assembly/routes、asset_library/routes 的错误封装也不同。

应先统一错误数据的展示适配，再补齐公共错误组件的调用方。不能只换 UI 外壳却丢掉后端原文，也不能为统一状态码改变既有“已提交但登记待完成”等语义。已有旧记录缺少原始详情时只能显示实际存下的内容。

**C. 制作参数的内部组合：外壳统一了，目录刷新与 LoRA 槽还分散。**

`features/workflow-settings/index.js:73、78` 与 `modes/video-assembly/settings.js:41、47` 分别拼 LoRA 槽、目录说明与刷新按钮，并各自处理加载/失败。图片在 image-settings 中还需区分本地扫描和节点同步。

建议抽出模型目录状态区、LoRA 槽的公共呈现与事件绑定，适配层提供扫描时间/来源/错误、字段定义、槽数量、数值步长和回调。不能把本地刷新与在线节点同步合并成同一个动作。目录区外层间距已经由公共 productionSettingsMarkup 管理，不再重复修外壳。

种子同属这个问题：`ui/production-settings.js:90` 已有 seedFields，图片与接续使用；`features/prompts/authoring.js:16` 仍手写种子控件。原三视频种子是片段级，应保持位置和作用域，仅统一控件、禁用/提示和数值验证。接续 settings 当前传 lastSeed:null，尚未将已有实际种子传给这个控件，不应显示成“所有模式的历史种子提示已一致”。

**D. 底栏补齐现有入口，而不是再创建新组件。**

`modes/swap/workspace.js:50` 的第一步 sourcePage 仍手写 savebar，绕过 workspaceActions；编辑步骤、图片和接续已有共用。建议只接入现有组件，保留“准备并继续”和源视频准备状态。这里属于覆盖缺口，不是缺一套新的底栏设计。

**E. 普通输入/选择弹窗的完成与关闭契约。**

基础 scopedModal 和制作参数的 openProductionSettings 已处理部分生命周期，但 `app/image-workspace-controller.js:203` 的 askText/chooseMedia、`features/image-results/transfer.js` 的分镜选择、资产 input-dialog 等仍各自构造 Promise、取消按钮、关闭及取值回调。

可在 ui 下提供小型输入/选择对话框控制器，统一确认/取消/Esc/关闭/路由中断/迟到请求处理，内容仍用插槽。不要从某个资产页面导入对话框来当全站基础设施。此处是重复与风险审查，未宣称已经复现某个关闭死锁。

### 第二批：复用共同操作，保留媒体与业务特点

**F. 候选的状态、操作与恢复提示。**

图片及三视频使用 candidate-records；接续 `workspace.js:100、103` 自行处理候选列表、选用和移除按钮。共同状态可以映射为“运行/完成/失败/待确认/选用/已移除”，公共组件提供动作槽和文案。后台仍分别校验权限与状态，不能仅凭前端映射决定是否可删除。

候选主预览不必统一成同一种卡片：图片的大画布、视频的源/结果对比、接续的片尾连播应保留；共用的是信息和动作框架。“选用此结果”在接续中会添加轨道，在图片中只选定输出，这两种后果必须明确区分。

**G. 媒体播放器的基础体验。**

- `ui/media-player.js` 有加载状态、重试、独立打开和播放位置处理。
- `features/asset-picker/media-view.js:31` 另有同名 mediaPlayer，支持图/声/视频但视频主要依赖原生控件。
- 接续 `workspace.js:72` 再手写 video。

建议统一基础播放、错误/重试、下载/独立打开及无素材状态，可配置 compact 或完整预览；资源库选段标记、波形、源/结果对比和接续片尾连播作为扩展。接续播放器与库内视频当前未接入公共播放器的那些增强行为，不等于浏览器原生控件不能播放。

**H. 上传反馈：进度与处理阶段应统一呈现，传输协议不强合并。**

core/upload-client.js 为原视频上传使用 XHR 字节进度；asset-picker/library-client.js 为资产库使用分块续传；图片与接续导入通过自己的 FormData/API。可共用“选择→传输→服务器处理→成功/失败/取消”的状态呈现和错误适配。分块续传、普通上传和本地文件收集具有不同协议，不能替换成一个固定 URL 的上传函数。

### 第三批：抽取稳定机制，避免一次重写状态机

**I. 保存、异步读取与草稿保护的机制复用。**

ProjectSession、ImageSession、接续 workspace 中的 session/save/action 各自维护 dirty/working/disposed/版本和保存。视频与接续共用 watchProject；图片 `app/image-workspace-controller.js:205` 独立轮询，且仅有运行任务时读取，周期也不同。

适合抽取的是：单次保存防重、可取消读取循环、实例存活判定、接收响应前复核编辑版本、统一保存状态反馈。payload 构建、变更影响确认、图片跨库 apply token 补登记、接续轨道/续写段保存必须继续适配。不能直接把三种 Session 合成一个巨型类，也不能默认把图片轮询周期/活跃条件改成视频。

**J. 媒体基础工具和错误封装。**

`h3ui/studio_media.py:11` 与 `asset_library/media.py:11` 都实现分块 SHA256；接续已导入前者。三处媒体命令包装分别有不同的超时、输出类型、取消和子进程清理。优先考虑无业务含义的流式哈希、标准错误信息；若提取进程执行器，必须保留取消归属、bytes/text 接口和超时行为。

尾帧预处理、图片几何、导出补边/裁切、音轨处理不能因为都用了 FFmpeg 就合并成同一转换规则。此前黑边修复已经说明：导出规格不能直接套到生成上下文。

## 4. 不应强行统一的内容

| 内容 | 原因 |
|---|---|
| 五模式完整工作区/相同步数 | 输入对象和创作过程不同，统一壳与导航即可 |
| 所有制作参数的完整字段清单 | 图像、视频、外部尾部上下文和导出具有不同参数语义 |
| 所有生成默认值 | 必须来自各自实际配方/工具，不能为了通用 UI 改生成语义 |
| 一个通用生成状态机 | 图片输出、多任务视频审核、接续依赖、未知提交恢复的条件不同 |
| 轨道、分镜、图片任务的数据结构 | 都是左栏列表但用户操作后果不同；共用列表样式不等于同一数据模型 |
| 资产绑定包/A-B 输入/接续逐项引用 | 能力边界不同，不应为统一组件自动增加或替换引用 |
| 成片导出与 AI 片尾准备 | 容器与进度可共用，实际处理语义必须分开 |

## 5. 建议的维护方式与验收

先复用现有组件，缺少稳定公共入口时再小范围提取。每个公共组件应写清楚：归属文件、调用模式、输入数据、允许的业务插槽、事件、取消/关闭行为、样式归属，以及不承担的职责。公共层不依赖模式私有字段或隐式 DOM ID。

建议顺序：页头/步骤与底栏覆盖 → 错误反馈与普通弹窗 → 参数内部组合 → 候选/播放/上传 → 保存读取机制与媒体工具。每批有独立检查和可回退边界，避免同时迁移所有工作区。

UI 改动核对受影响模式的正常/空/失败/长文本和窄屏；UX 改动核对取消、重复确认、保存冲突、迟到响应与路由切换。字段/保存适配另需真实隔离 API→保存→快照/离线编译验证；媒体基础工具另测合成素材原字节、时长/帧序、取消和清理。公共呈现合并不得自动提交生成。

本轮只完成静态调用链和实现对照；“重复存在”来自实际代码，“优先合并后的收益”属于工程判断，不是已实施结果或运行故障诊断。未重复计入上一轮测试，没有修改业务代码、静态版本或 GitHub。
