# 资产库使用与维护

本文沿用本地创作服务器／资产库 V2 的数据与使用约定；V2 不是当前网站版本。当前状态见 [维护基线](maintenance-baseline.md)。

图片编辑任务废弃不会删除已入库资产、版本或视频固定引用。任务与原候选可从回收站“项目移除的”恢复；原始数据留存，恢复不自动选用或生成。

项目内的[候选移除](candidate-records.md)不回收已入库资产，也不改旧项目固定引用。已移除候选不再列入可入库输出；以前发放的候选输出令牌在实际入库时重查可见性，先恢复再入库。图片继续编辑和选用同样校验标记；恢复不自动建立资产或引用。

资产库侧栏[回收站](recycle-bin.md)现为统一分类入口：资产库移除的、项目移除的、生成移除的。已移除资产仍可查看详情和批量恢复；项目/生成按所属记录逐条恢复。旧资产回收站链接兼容，独立资产版本与旧项目固定引用保持。

## 日常使用

顶部“资产库”是独立入口。图片、声音、视频与工作流 JSON 均可存档；角色、场景、物品、服装、饰品、声音、色系、视频、控制参考和材质是用途分类，允许多选。分类、合集、标签不改变底层输入节点。

1. 点击“导入素材”选择一个或多个本地文件；页面先显示体积，再确认导入。大文件按块上传，中断后重新选择同一个文件可接着传。每项独立显示状态，失败项可重试。
2. 在详情中填写名称、资料 PROMPT、设定、绑定项并保存。资料编辑产生新版本。**资料不会自动写入任何制作提示词。** “复制资料”后由你主动粘贴到片段正文才成为制作输入。
3. 主媒体与备选媒体分开选择。可以切换主媒体、选择封面图。视频先抽取当前／首／尾帧生成图片，再用“选择封面图”指定；封面不替代生成输入。
4. 视频可标入出点、循环选段、截取视频、抽帧、提取声音；图片可裁切、旋转、缩放。均另存为派生资产，原件不变。尾帧按视频实际呈现顺序抽取，不按24fps猜帧号。
5. “更多导入方式 → 收集输出文件夹”只检查指定目录，默认不递归；仍在写入、格式不支持等文件跳过并列原因。勾选后才入库。可以从原生 ComfyUI 的输出目录收集，无需生成引擎运行。
6. 选择多项可批量整理、加入合集、比较候选、导出素材包或移入回收站。包内是否包含启用的绑定、资料、来源工作流分别勾选；导入包会核验相对路径和文件哈希，不运行附件工作流、不安装模型。

## 在三个视频创作模式中调用

- 每个片段的“从资产库选择”与本地上传并列；文生模式先展开“加入本段参考资产”。换人的源视频有独立“从资产库选源视频”入口，并可选使用区间。
- 选择角色后显示默认绑定的图片、声线等。每项可取消、改用途或换备选；角色与声线使用同一个角色编号。两个角色的编号应分别设置。替换声线、服装等时，勾选同角色的旧素材作为替换对象，避免重复。
- 点击“检查引用与工作流”，核对变化后才“确认应用”。纯 T2VA 加入媒体会说明切换到参考配方；取消则保持原配方、提示词与素材。换人只能有一张角色图；源片原声与新声线冲突时必须明确选择声音策略。
- 当前 H3 没有接入的遮罩、控制图、饰品或材质专用输入可以收藏和导出，但不会伪装成角色图传入工作流。
- 项目使用固定版本的独立副本。库中改名、更新或回收，不影响旧项目。根资产卡片的“检查库中更新版本”会展示新版媒体与绑定，并预选替换旧绑定包；确认后只改变本次引用及其明确列出的后续影响。
- “沿用P1”“本段指定”“不使用素材”继续有效。不使用素材时不会被角色绑定补回图片或声音；连续段的声画上下文仍由工作流独立处理。
- 制作前“检查工作流”可查看实际编译图、媒体编号、节点及库版本。结构通过不等于已经验证画质或峰值显存。

第四功能的图片输入、候选入库及“用于视频”流程见 [图片模块](image-assets.md)，继续复用同一资产库与固定版本边界，不把图片任务改成视频片段。图片第二步下载按钮旁可直接“加入资产库”，按当前查看候选的固定ID入库，不切第三步、不改变已选用结果。复用图片原入库接口、文件哈希核对、生成来源和幂等键；成功显示资产详情链接，重复请求不新建重复版本。请求 select_output=false；第三步省略或传true继续原选用语义。旧后台缺 catalog.quick_ingest_preserves_selection=true 时快捷入口提示重启网站，不能默默按旧逻辑选用。图片制作参数以当前图片任务为作用域，应用只写任务草稿；保存、取消或模型刷新均不替换已选候选、库版本和视频中的固定引用。参数修复未迁移资产数据或改变原入库／引用确认流程。

## 生成结果回收

项目素材、每个候选视频、选用结果和最终成片都有入库入口。必须指定确切结果；后台不会换成最新候选。记录原文件、来源项目、分段清单与实际存在的运行文件；生成时的 PROMPT 复制为资料，原始运行记录另行保存。合成长片保留分段来源，不伪造唯一种子。

已有项目上传的图片如果仍有原始文件，入库优先保留原始字节，包括透明通道。项目的标准化输入副本与资产原件是两份职责不同的文件。删除项目之前请确认需要的结果已经完成入库。

## 网站与生成引擎

资产、编排、备份、预览和本地媒体处理不要求运行 ComfyUI。三个视频模式与图片模块的“刷新本地模型列表”共用本地文件扫描，不连接引擎；图片“同步节点能力”是单独的在线动作。图片配置为远程引擎时，普通刷新使用匹配该引擎地址的缓存并明确来源，不以本机目录冒充远端文件。具体发现路径、当前选择保留及错误反馈见 [模型目录](local-model-catalog.md)。节点声明/缓存不证明模型已安装或兼容，实际生成仍需引擎核验。

“资产库 → 本地存储与备份 → 生成引擎启动设置”是可选项，默认关闭。只有用户填写实际 Python 程序、ComfyUI 的 main.py 和参数，通过文件结构核验并启用后，生成请求在连接失败时才尝试启动；不自动停止引擎。脚本变化后要重新核对。此版本没有为用户启用或实测自动启动；隔离验收禁止启动引擎。

GPU处理一次一项，本地媒体处理默认两项；同一项目的依赖变更仍串行。其他项目与资产库可继续编辑。生成期间的新草稿独立保存，对本次运行不生效；完成后载入草稿，经正常变更确认用于下一次制作。

重启会尝试对账已登记的活动任务，只恢复监控，不重新提交。连接短暂失败有有限退避；仍不能确定结果时保留“待确认”，先查询恢复再决定重试。网站不会根据不精确的文本匹配猜测哪个 ComfyUI 任务属于本次运行。

## 数据目录与备份

- 网站代码及模板：安装目录。
- 项目与执行副本：`studio_data_dir`，默认 `data_v5`。
- 跨项目资产库：`asset_library_dir`，默认安装目录同级 `TimeForestAssets`。
- 库内 `objects` 保存按哈希去重的原件；`previews` 为浏览衍生图；`manifests` 为可重建版本清单；`staging` 为传输／媒体临时区；`exports` 为素材包；`backups` 为完整备份。
- 数据库 `library.sqlite3` 是权威记录。不要运行中直接复制 SQLite 主文件而遗漏 WAL。页面“创建完整备份”使用一致性备份，并复制对应原件、核对哈希。
- 原件、资产数据库、项目、模型、实际配置、日志与备份不纳入 Git。

### 迁移与恢复：先停止网站

目录切换涉及在途上传与两个存储位置，因此使用独立维护工具；网站页面提供这份说明。先让任务结束，关闭网站服务，再在安装目录执行。示例中 Python 路径根据本站安装填写；不会启动 ComfyUI。

```powershell
$env:PYTHONPATH='.'
# 只预览，不切换
.\.venv\Scripts\python.exe tools\library_maintenance.py migrate --config config.json --target D:\MyAssets\TimeForest
# 核对后执行，目标必须尚不存在
.\.venv\Scripts\python.exe tools\library_maintenance.py migrate --config config.json --target D:\MyAssets\TimeForest --apply
```

工具先复制原件和数据库，核验哈希，迁移预览／未完成缓冲，最后才原子切换配置；原库和切换前配置都保留。目标已存在、路径嵌套、目录越界、网站仍运行或复制失败都会停止，不改用半个新库。之后启动网站，新路径才生效。迁移失败产生的目标目录保留供排查，重试使用另一个不存在的目录。

从完整备份恢复到新目录：

```powershell
.\.venv\Scripts\python.exe tools\library_maintenance.py restore --config config.json --backup D:\Backups\chosen-backup --target D:\MyAssets\Restored
.\.venv\Scripts\python.exe tools\library_maintenance.py restore --config config.json --backup D:\Backups\chosen-backup --target D:\MyAssets\Restored --apply
```

只复制备份清单列出的数据库和媒体。备份不含未完成上传缓冲；恢复后应重新上传这些文件，不能把它们误认为已入库资产。原有版本、绑定和原件均恢复；预览可在媒体再次处理或导入时生成，原件仍可查看。

若仅需撤回一次迁移，在未往新库写入新资产前，关闭网站并恢复工具保存的 `config.json.before-library-*.json`。若新库已有新增内容，先导出新内容再回退，不能直接丢弃。

### 保留与清理策略

默认永久保留原件、不可变版本、回收站内容、项目引用记录与备份。本期不做不可逆的资产版本清空，避免绑定和历史项目断链。类别删除只迁移分类关系，不删资产。

维护工具仅允许清理至少7天前已完成的派生任务临时目录，先列实际路径与体积；未完成／失败任务、上传缓冲、原件、回收站和备份一律保留。

```powershell
.\.venv\Scripts\python.exe tools\library_maintenance.py cleanup --config config.json
.\.venv\Scripts\python.exe tools\library_maintenance.py cleanup --config config.json --apply
```

## 常见情况

- 普通网站启动保留原本的本地任务恢复行为。维护图片前后端版本时可用 `run.py --no-browser --no-startup-recovery` 跳过本次已有 running 状态重写及 queued 唤醒，不回写配置、不迁移数据库；之后主动操作仍沿原流程。仅用于已授权且无活动任务的网站维护重载，详见[检查与交付](governance/checks-and-release.md)。

- 浏览器收起上传时暂停传输；已提交的本地处理仍在“处理任务”中。重新选择同文件续传，已完成项不重复。
- 路径中原件损坏或空间不足：任务明确失败，不发布坏资产；解决原因后重试。并发编辑冲突时保留页面资料草稿，载入最新版本核对后保存。
- 原文件没有模型／LoRA／工作流元数据：显示记录缺失，不根据画面猜测。某些媒体转换会丢失容器内元数据，因此来源链另外保存在库里。
- 浏览器无法播放编码：使用“生成兼容播放副本”，原件不变；长视频处理可能较久，页面显示阶段进度，不能把阶段进度当帧级精确百分比。
- 素材包会移除已识别的凭据字段和独立绝对路径；无法承诺识别任意自由文本内的所有秘密。分享时主动决定是否携带资料和工作流，并检查自己的文本。
- 本版验证了结构和本地媒体链路，未运行 H3 生成、未验证口型／身份／多角色效果，也未证明任意数量资产能在16GB显存下生成。


## 导演工作区 V3 的界面位置

网站顶部[当前任务队列](task-queue.md)汇总本地 queued/running 处理；历史与重试仍在资产库。尚未开始的处理可确认取消，执行前条件更新防止与调度器抢占竞态；运行中文件操作会完成当前处理，不宣称杀掉子进程。队列读取保留所有活动行，不因最近100条历史限制漏掉长时间排队任务。

资产库保留独立本地目录与数据库，本次仅统一布局和命令位置，不迁移原件。分类列表和结果区独立滚动；详情左侧媒体，右侧资料编辑，保存固定在资料区底部。收集文件夹、导入素材包位于“更多导入方式”；批量导出随选择出现；迁移与恢复仍在“本地存储与备份”。

三个创作模式共用素材选择及版本确认。当前片段的素材属性提供本地上传/资产库选择；每份素材的“管理素材”收纳编辑、移除与入库/版本操作。资料PROMPT与生成正文保持分离。绑定素材导致工作流根本冲突时仍显示影响确认，取消不留下部分引用。

文生图结果继续复用图片候选的快捷入库/第三步入库和固定来源快照，image_tool=text；资产库图片工具筛选补充“文生图”。入库不更改原任务生成条件，结果可继续编辑为单图任务或经既有流程引用到视频。
