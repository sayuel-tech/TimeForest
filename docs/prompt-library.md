# 统一提示词库

本地6.3.32实现，执行范围见[方案V3及阶段账本](product/prompt-library-execution-plan.md)。提示词库是全局管理工具，不是第六个生成模式。未来剧本创作与LLM仍由后续方案确定。

## 使用

全局导航进入“提示词库”，按 **视频／图片／剧本 → 模型家族 → 提示词** 管理。当前视频工作流归H3，图片五工具归Krea2；通用用于主动整理跨模型文字，待归类保留尚未核实的模型来源。新增分支不安装模型，也不改变生成工作流。

在五模式中照常写提示词、保存项目。保存成功后会自动收录各片段、任务或续写段的非空文字；相同目标和家族重复保存不新增条目，正文修改保留新内容版本。切换到另一家族保留原家族使用记录。换人项目默认完整正文、片段完整正文与补充说明分开记录；无独立文字的继承段不重复收录。

每个正文编辑区共用“从提示词库选择／收藏／复制／展开编辑”。选择后明确替换或插入，只应用当前草稿；取消保留原内容。已保存且未变化的创作记录可以直接收藏；尚未保存的内容可另存并收藏模板，不会替用户保存项目。展开编辑同样需要应用，再走原项目保存。基于库版本的草稿保留固定版本标记，后来手改会显示“已修改”。

参考图长视频和文生视频支持字段组合，应用前逐项勾选正文、声音等字段。未选字段保留；仅在应用正文时同步组合保存的structured/full方式。图片与接续不支持的字段会明确列出，不静默丢失。引用检查复用原素材清单和发声顺序规则；缺失编号可取消，或保留文字后自行调整，不自动增加素材或重排编号。

库内支持搜索名称、正文和标签，筛选创作记录／模板／收藏，并可勾选全库查找。模型分支可新增、命名、排序、移除恢复；空分支也可管理。通用和仍被来源配置依赖的家族受保护。移除分支不删正文；回收站可查看、移动条目及恢复分类，单独移除的提示词不会跟随分类自动恢复。

创作记录的正文对应项目保存事实。库内编辑它会另存为独立模板；名字、标签、收藏、管理分类可另行整理，后续项目保存不会撤销这些整理，也不会复活已移除条目。移动不改变正文版本，另存副本保留原条目及版本来源。剧本分支现在即可保存普通创作指令，不需要接入LLM。

## 保存异常与备份

项目保存失败不收录。项目已保存但库失败时，工作区单独显示提示词补记提示；“补记已保存提示词”只重试那次保存快照，不再次保存项目、不读取后来的草稿、不生成。成功凭据幂等；迟到旧凭据不覆盖较新的创作记录。如果项目盘也无法写补记凭据，会明确提示保留文字另存。未知家族不阻止项目保存。

默认数据库为项目数据目录下的 `prompt_library/prompts.sqlite3`；可用 `prompt_library_dir` 指定独立目录（相对网站配置根目录解析）。`prompt_receipts/` 始终在项目数据目录下，成功后只保留小型回执，失败时保留当次收录所需的正文/模型快照。库按需初始化，库目录不可写不阻止网站启动。

库页“备份提示词库”通过SQLite备份接口下载一致的数据库，包含分类、条目和内容版本。这与资产库备份分开。恢复时先停止导演台、备份现有库目录，将下载的库放回实际目录并命名为 `prompts.sqlite3`，原库及其WAL/SHM文件一并保存在另一个备份目录，避免把旧日志留在恢复库旁；再启动网站。未补记的回执另备份项目数据目录中的 `prompt_receipts/`。本轮没有操作真实数据的恢复。

数据库、回执、失败快照和备份都属于用户数据，不进入GitHub、独立工作流包或截图示例。默认位于既有忽略的data_v5下；根目录同名路径也已加入忽略与分享检查。自定义目录应放仓库外。此功能不批量扫描历史项目，也不迁移原项目／资产数据库。

## 生成记录与来源

结果操作区及资产来源区提供“查看生成时提示词”。原视频读对应运行目录的prompt.txt和manifest，图片读确切输出所属运行快照，视频接续读确切续接快照。复合成片按固定导出身份、片段顺序及选中的内部任务分别展示；库引用只沿固定asset/version/media读取。没有记录就显示空缺，不以现在的项目文字、配方默认值或ComfyUI图JSON补齐。

可复制、另存收藏；有明确当前编辑目标的结果页可以确认后“用于当前草稿”，视频完整正文会明示作用方式，并保留记录来源标记。来源面板本身不推断编辑目标。库条目复用原来源项目跳转与移除／缺失反馈。外部素材包不关联本机同编号项目。记录遍历有限额；旧缺失关系和无法定位的成片内部记录不能补造。

## 代码归属与接口

| 职责 | 入口 |
|---|---|
| 独立库、分类、revision、固定版本、事务 | `h3ui/prompt_library/store.py` |
| 同次保存快照、幂等凭据、家族解析 | `h3ui/prompt_library/{service,families}.py` |
| 真实记录、可选来源标记、输入警告 | `h3ui/prompt_library/{records,provenance,validation}.py` |
| API组装 | `h3ui/prompt_library/routes.py`、`h3ui/__init__.py` |
| 公共工具栏及展开编辑外壳 | `static/studio/ui/prompt-editor.js` |
| 库浏览、模板／分类编辑、选择／应用协调 | `static/studio/features/prompt-library/{browser,editor,tools}.js` |
| 五模式字段适配、记录查看、补记反馈 | 同目录 `{adapters,records,collection}.js` |
| 全局页面／导航／样式 | `pages/prompt-library/index.js`、`app/bootstrap.js`、`styles/prompt-library.css`（均在static/studio下） |

API前缀 `/api/v5/prompt-library`。catalog声明 `prompt_library_version=1`；identify返回实际模型的family/evidence/model。entries支持用途/分支/待归类/类型/收藏/文本/回收筛选和分页，POST变更须携带revision。固定内容通过entries/{id}/versions/{version}读取。model-branches负责分类；favorite-current只匹配未变的已保存记录；pending及receipts/{token}/retry负责补记；records/{project}与asset-records/{asset}负责确切生成文字。backup独立下载数据库。旧后台缺能力明确提示重启。

原视频apply、运行期间独立draft、图片apply、接续save，以及原视频确认资产引用时提交的项目草稿都接入收录。只接真实提交点，不在预览、输入、选择、生成进度轮询或读取来源时写库。库与项目分库，库错误不改原保存成功事实。`prompt_sources`为可选来源元数据，经原保存门持久化；原生成编译器不读取它作指令。

## 新模型、新模式与剧本接入

1. 先确认当前工作流承担生成的主模型及作者上游来源，证据维护在方案4.3与families.py。H3的hybrid/ref/fl及量化版本不拆家族，Krea2的辅助Qwen编码器/VAE不决定分类。日常保存离线匹配，不联网传提示词。
2. 新家族在库中新增分支并保持稳定family标识，例如视频分支 `wan`。已核实的模型可通过配置 `prompt_model_families` 增补：每项包含 `purpose`、实际完整相对模型文件名 `model`、`family`、作者来源链接 `evidence`。例子中的Wan2.2版本应保存在来源model，分类为Wan；文件及证据必须核实后填写，不把占位名称写成已支持。维护配置后重启网站加载。未登记仅影响整理分类，不限制模型选择或执行。
3. 新调用方在feature适配层声明目的、实际主模型、稳定目标/范围、允许字段、原文读写、编辑代次、可写状态、原输入校验、标记dirty及重绘。调用共同tools/ui，不复制模式专属工具栏和CSS。应用后走原保存门；来源标记与正文同次保存。
4. 新保存入口提交成功后传固定快照给Library.capture；不能把界面实时对象当作重试数据。新生成结果类型接records，只读取历史实际文本和精确身份。
5. 未来剧本作品、章节场次、LLM会话、候选与服务配置分别由其模块拥有；库只拥有可复用内容与版本。未来内容类型在store.content和catalog中版本化扩展，并提供对应编辑适配，未知格式不得当代码执行。LLM选中固定版本不等于同意发送整个库；云端发送范围和候选采用由未来用户流程明确，密钥不进入库条目。本期没有LLM客户端、联网生成或剧本页面。

新增调用方同批提供分类保存、取消、版本、引用不匹配、库失败补记和固定记录的必要证据，登记[体验准入](frontend/experience-admission.md)。不能仅因导入公共函数就宣称操作一致。
