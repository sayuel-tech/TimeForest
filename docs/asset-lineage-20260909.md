# 资产派生追溯交付 · 本地6.3.29

本批接续6.3.28，实施资产方案第三阶段的上游链、已入库下游查找和相关异常。第一阶段来源/项目跳转/参数展示及第二阶段五模式核心添加/管理/入库继续保留。第三阶段本批范围已实现；不能据此宣称全部历史来源、未入库下游与外部包身份映射都完成。

## 实际实现

- 资产详情与选择器共用“查看上游派生链”，默认折叠。视频接续读取生成时的snapshot.source.origin，支持P111→P11→原素材及跨库固定版本继续追溯；不受目录排序、当前选用或当前制作参数影响。
- 图片继续编辑可经过未入库的中间输出追溯到原素材。只读取执行快照inputs中的有效A/B/标注，区分底图与参考图；不凭任务parent_output推断。更换A后残留旧parent_output、文生图残留输入、非双图B均不能构成虚假父关系。
- CPU派生读取asset/version/media/hash；视频接续成片按冻结parts展开。前三视频成片按保存的selected顺序匹配selected_runs，展示确切片段候选和当时参数，不读取今天的选用列表。
- 上游生成记录链接带确切run/output/task/segment及原资产返回位置，沿既有source-target只读定位。上游参数与当前资产参数分别折叠，不自动应用。
- 新增“查看已入库的下游结果”：使用同一解析器验证完整上游关系，反查固定版本的后继资产。包含历史版本与已移除资产，和历史refs使用记录分开。只有主动展开才扫描，每批最多25个媒体版本，分页固定本次版本上界；不会因库较大而自动遍历到底。
- 查找失败保留已有结果，重试同一批；迟到响应不得写入已经移除的显示容器。无匹配只表示本次范围未发现已记录结果，不表示没有派生。来源缺失/外部身份/循环/展开限额导致的不完整会计数提示。

## 异常与边界

1. 固定版本/媒体/摘要必须同时匹配，不能替代为最新版本。缺失、移除、任务废弃、循环、16层深度与64项总量上限均有明确显示。读取不恢复数据、不改项目，不触碰原件。
2. 旧图片缺少执行输入快照不从当前任务补齐。前三视频旧previous只有上下文文件/检查点路径时标为缺少身份，不解析文件名冒充候选ID，也不向页面暴露这些路径。
3. 素材包采用外部身份边界，不将原编号与本机相同编号自动关联。现有包已删去部分来源字段，不能声称关系可完整恢复；本批没有修改包格式或迁移旧数据。
4. 反向查找范围为已经入库的媒体版本；同一媒体的历史版本会分别列出。可经仍保存的未入库中间运行推导已入库后继，但不枚举所有未入库结果。删除中间记录后不能靠历史使用记录补造链。
5. 尚待后续：前三视频未来运行的明确上游身份契约、未入库结果的反向总览、外部包关系的显式身份映射。旧数据不可推断部分将始终保留未知。真实生成、日常大量资产场景仍待用户体验。
