# 视频拼接模式开发计划

状态：原始计划保留。用户随后授权执行，本地6.3.12已完成代码接入和隔离检查，现行行为及必要实现差异见[视频拼接说明](../video-assembly.md)，真实生成与体验仍待验。下文是6.3.11时制定的计划，不作为已实现接口清单。本计划依据本地当前代码与仓库保存的工作流快照编写，不代表上游最新模板或生成效果已经验证。

用户已确认“尾帧延长”指 **沿视频结尾继续生成动作和画面**。制定计划时只整理思路；执行交接以维护基线为准，当前用户仍禁止自动更新GitHub。

## 1. 产品定位与首版范围

新增独立入口 **视频拼接**，建议模式 ID 为 `video_assembly`，以已有视频为创作起点：从资产库或本地导入多个视频，排列成片；按需延长某段视频的结尾，反复筛选续接结果，再输出完整视频。

它与参考视频换人的输入目的不同：原片段进入成片，不要求换角色或重新生成原表演。两个工作流属于这个模式内部的 AI 续接选项，不各建一个模式。

| 能力 | 首版设计 |
|---|---|
| 视频来源 | 多选资产库视频、多选本地视频，可在同一项目混合使用；固定来源版本，保留原件 |
| 编排 | 增加、排序、预览、移除片段；设置使用起止点，默认完整使用；显示顺序和预计总时长 |
| 普通拼接 | 仅本地媒体处理，无需 ComfyUI；不生成、不占 GPU 生成通道 |
| AI 尾部续接 | 为选中片段添加续写段，填写后续画面与声音描述、希望新增的时长；跳舞与官方两种工作流可选 |
| 反复制作 | 重新生成追加候选；预览“原片尾＋续接”，选用满意结果；支持沿已选续接继续添加下一段 |
| 成片与复用 | 拼接导出、下载；续接候选及完整成片均可加入资产库，保留来源记录 |
| 过程管理 | 共用活动任务列表、停止、计时、错误、保存与恢复；支持移除无效候选和分类回收站 |

首版使用单一顺序片段列表，不引入多轨剪辑、字幕、调色、配乐轨或复杂转场。尾帧定格不在本次需求内。普通接缝采用直接切换，AI 续接只延续前一段，不自动保证与后一个任意视频匹配，也不暗中生成桥接镜头。

例如：`视频 A → A 的已选续接 → 视频 B → 视频 C → C 的已选续接`。A 的续接不满意，只重新制作该续接；A、B、C 的原视频不会因此重做。只有一个视频也能创建项目并续接。

## 2. 三步工作区与主要动作

沿用纸色、森林绿、公共工作区、左侧目录、中央预览、右侧属性的现有设计。时间呈现使用图片模式已认可的公共计时组件，不复制一套样式。

### 第一步：视频与排序

- 空态提供“从资产库选择”“导入本地视频”；导入后左侧为有缩略图和时长的片段目录，支持拖动排序及上移/下移按钮。
- 中央预览当前视频；起止点作为片段编辑操作就近呈现，不放入生成参数弹窗。采用非破坏裁切，仅保存使用范围。
- 右侧展示来源、使用范围、尺寸、帧率和音轨信息。不同尺寸的视频在导出时如何适配需提前可见。
- 主要动作“下一步”；只想拼接时可明确选择“直接拼接导出”，不强迫填写提示词、选择模型或在线检查引擎。
- 移除仅从当前编排移除条目；不删除资产或源文件。已有关联续接时说明影响，保留可恢复记录；不能移除正在处理的输入。

### 第二步：续接与挑选

- 每个原片段下面可“添加续接”，续写对象清楚标明是哪个片段或哪个已选结果的末尾。整部影片末尾延长就是最后一个片段的续接，无需另造一套工具。
- 输入后续描述及希望新增时长。沿用当前长视频规划处理合法帧数和必要内部任务，界面区分“希望新增”“预计实际新增”，不将包含上下文的模型输出时长冒充新增时长。
- 顶部唯一“制作参数”编辑当前续写段；侧栏不重复设置入口。无选中续写段时说明当前作用域，不能让用户误以为会修改全部原视频。
- 按钮为“生成续接／重新生成”“选用此结果”“继续续接”；下方导航为“返回上一步”“拼接导出”。不满意时重新生成沿用同一输入与草稿，只追加候选，不偷偷把失败候选当下一次输入。
- 提供原片尾与续接的连播检查、候选切换、下载、快捷加入资产库、移除无效结果。候选入库与选用是两个动作，收藏不自动改变成片。
- 原片段可以不续接；已经添加但尚未选定的续写段需完成、暂不纳入或移除后再导出，不能静默跳过。

### 第三步：成片

- 汇总最终顺序、使用范围、已选续接、预计时长和输出规格；“开始拼接”创建独立导出快照。
- 导出成功后播放、下载完整视频及加入资产库。旧成片保留，不因下一次修改排序或重导出而覆盖文件。
- 运行时显示共享计时和实际处理阶段；停止保留已完成候选与上次成片，未完成文件不能列为成功成片。

## 3. 两种 AI 续接工作流

两者仅影响新增续接段。普通拼接由媒体处理服务完成，不使用这两个图去重生成原视频。

| 网站选项（拟定） | 依据与保留部分 | 必须新增的适配 |
|---|---|---|
| 跳舞工作流 · 8＋4 续接 | `h3ui/studio_sources/dance.json` 与当前 `dance_split` 编译路径；保留已有模型加载、两段采样、latent 放大与声画输出机制 | 外部视频的解码尾部、独立音频尾部、目标尺寸上下文；首个续写任务也必须注入前文；裁掉上下文后只交付新增部分 |
| 官方工作流 · 续接适配 | 优先以仓库 `official_r2v.json` 的 `MiniMaxH3ReferenceToVideo` 和原生声画链为基础，参照现有官方配方参数及采样路径 | 复用网站已有 motion-context 思路，补齐外部声画尾部接入、长度规划、输出裁切与结果回收；不要求额外角色图，不将整段原片绑定为换人参考视频 |

选择官方 Ref2VA 作为初始适配基线，是因为它与当前跳舞链共用声画条件接口，已有网站续接代码可核对；不是声称官方发布了“时间森林视频拼接”模板。`official_t2v.json` 可作为文字条件差异的补充核对材料，不在首版额外增加第三个选项。

原始跳舞图和官方 Ref2VA 图都不包含网站完整的外部视频续接管理。新选项名称和来源记录必须区分“原图”与“网站补充适配”，不称“官方原生无缝续接”。实现前先离线证明两条图均实际消费尾部视频、音频、正文和当前参数；若某节点接口不支持该组合，记录具体缺口并调整局部适配，不用空接线交付。

新增模式专用适配 ID 与 revision，引用已有编译能力，保留旧三视频配方 ID、默认值和图语义。拟将跳舞方案作为新项目的初始选择，用户可切换到官方；这是新模式的建议默认，不修改旧模式默认。

### 制作参数

沿用后台参数描述 → 公共控件 → 临时草稿 → 应用/保存 → 实际编译绑定。计划分为“工作流与模型”“生成尺寸”“采样与种子”“声音与适用优化”；只公开所选图消费的字段。导出规格属于项目范围，生成设置属于续写段范围，弹窗需明确分组及作用域。

- 跳舞显示真实两段采样相关参数；官方显示对应官方采样和可选加速参数。不能把跳舞专属字段放到官方页假装可调。
- 取消无副作用，应用经原保存门，保存后重读一致；恢复默认只影响当前作用域的临时副本，保留视频、裁切、正文及候选。
- 模型刷新沿用本地文件目录与当前选择保留规则；不自动启动引擎或全量展示插件字段。
- 固定种子（含 0）与随机种子沿用共同语义，每次运行冻结实际种子；切换工作流不自动试参。
- 每条续写段分别保存两种工作流草稿，切换时保留另一份；重新准备与当前配方绑定的尾部上下文，不跨模型/VAE偷用旧 latent。历史候选继续可看，新生成不继承不兼容中间态。

详细字段名称、合法范围、默认来源和节点落点在开发时写入唯一[参数映射](../frontend/parameter-map.md)，本计划不另造一份可能漂移的参数常量表。

## 5. 媒体、时长与连续性的处理规则

**拼接媒体。** 探测每段的真实时长、显示方向、分辨率、帧率及音轨。输出画布初始取首个视频的显示尺寸并在项目建立时冻结，后续排序不暗改画布；像素格式所需取整需在规格中可见。首版建议默认 24fps，与当前生成链一致，导出选项复用现有可用规格。混合帧率/VFR按时间戳转换，不通过更改播放速度凑帧数。

不同长宽比默认等比例适配并补边，不拉伸、不暗裁人物；需要填满时由用户明确选择裁切。用于模型的处理尺寸与最终导出尺寸分开记录，跳舞链的放大结果不能反过来改变原视频裁切。原视频编码为项目处理副本，不改写原件；不把重编码导出宣传成无损拼接。

**音轨。** 原视频保留自己的声音；无音轨视频可正常拼接，在统一音轨中对应时间为静音。续接默认按适配图生成声音；需要静音时由用户明确选择。原声音、参考上下文与生成声音不能重复叠加，也不自动循环音乐或复制最后一秒作为新增声音。

无声原片的 AI 续接不能调用当前“缺音轨就失败”的生成结果校验冒充支持：适配需明确构造静音上下文、标注来源为无音轨，并离线检查图消费路径，真实效果留待验证。请求生成声音却未返回音轨时仍报错，不能偷偷补静音标记生成成功。

**尾部上下文。** 以用户裁切后的实际末尾为准，解码后按适配规格准备视频尾部和时间对齐的声音尾部。当前8＋4路径需要22帧图像、24帧声音上下文，它们是当前适配约束，不是全站永久规则。无损封装缓存只能避免再次有损压缩，不能恢复压缩源已经丢失的信息。

原片太短、不足目标上下文时仍允许普通拼接；AI 续接明确指出长度缺口，不暗中重复帧或退成单图生成。模型输出含上下文，必须裁除后才追加到原片，验证边界无重复帧和音频重复；长续接的内部任务也逐段遵守同一规则。

**依赖与版本。** 序列条目、续写段、候选都有稳定 ID。运行快照冻结来源资产版本/文件哈希、起止点、前置候选、配方与适配 revision、模型/VAE、尺寸、正文、参数及实际种子。改变输入末尾或上游选用，只让真正依赖它的续写选择需要重新确认，保留旧候选；单纯移动完整“原片＋续接”组不重生成。运行中可以保存后续草稿，但不能修改正在执行的快照。

## 6. 任务、保存与回收站

导入准备、AI 续接和最终拼接共用活动任务入口，显示项目、片段、实际阶段及持久时间；完成后退出全局列表，历史在项目内查看。不建立第五模式专用的全局队列。

GPU任务的取消/停止沿用精确任务归属检查。媒体处理仅控制自己持有的 FFmpeg 子进程，取消后回收进程、保留来源及历史成片；不能按进程名结束所有 FFmpeg。提交结果不明时保持待确认状态，不自动重试生成；刷新页面也不能重复提交。

项目列表移除仍进回收站“项目移除的”；序列条目移除作为该项目内可恢复子项，同类展示。续接候选和历史成片移除进“生成移除的”，资产移除仍进“资产库移除的”。新记录补充业务归属适配，复用现有标记/恢复机制。保护当前选用、处理中、待确认和下游依赖；恢复不自动选用、启动或恢复被单独移除的子结果。允许移除最后一个序列条目，保留空态与重新导入入口。

## 7. 实施顺序与每步验收

以下为后续开发顺序，不是本轮已执行步骤。每步同时更新相关文档、维护状态和必要 AGENTS；不等全部功能做完才补维护交接。

| 顺序 | 实际交付目标 | 必要检查 |
|---|---|---|
| P1：双工作流离线接入证明 | 固定本模式输入/结果契约，分别编译外部尾部续接图，确认声画、正文、种子和长度的真实落点 | 临时素材与假目录；两条图的默认/非默认绑定、22帧尾部及音频区间；缺输入和短视频明确失败；旧图编译对比不变 |
| P2：普通拼接完整路径 | 本地/库视频导入、保存重读、排序与范围、规范化、导出/停止、下载与入库；独立模式服务可用 | 合成测试视频覆盖有声/无声、混合尺寸/FPS、VFR、方向、中文文件名；实际 FFmpeg 导出时长/流/帧顺序和声画同步，不使用用户素材 |
| P3：AI 续接制作路径 | 两工作流选择、当前段参数、尾部准备、运行快照、候选回收、重生成与连续续写，按选用结果合成 | 隔离真实 API→前端→保存→编译；假引擎返回合成结果验证回收/裁上下文，错误/未知提交/精确停止；明确这不证明生成效果 |
| P4：统一体验与公开入口 | 三步页面、活动任务与公共计时、候选/序列恢复、资产来源；完成后才正式注册第五入口及能力标记 | 1280×720及窄屏、空/忙/失败/多候选、快速切页、取消/恢复默认/模型刷新、两配方草稿保留；旧四模式相关调用方回归 |
| P5：用户生成验收与分发 | 在用户后续授权的环境分别体验两工作流，确认结尾延续、声音、反复制作及长链效果；之后按发布授权分发 | 真实生成与视觉听觉验收单独记录；未授权前不执行。代码和适配工作流包分发仍分离，不把原工作流/模型TXT包上传 GitHub |

P1若发现实际条件接口缺口，先修正适配设计再推进 UI，不交付空参数页或未接线的工作流选择器。两条方案都完成实际接入才算满足本次开发目标；P2的纯拼接只是中间里程碑。真实生成验收未完成时，文档如实区分代码检查与效果验证。
