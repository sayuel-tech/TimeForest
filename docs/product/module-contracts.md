# 按用户任务组织的模块与工作流约定

本文件沿用 V4 阶段 A 合并的维护规则，并依据阶段 B 的实际代码接入更新功能边界。下列现状来自注册、工作区、编译器及现行说明的定点核对；相关非生成检查、用户体验与真实生成状态统一记在[维护基线](../maintenance-baseline.md)，不在此另建版本台账。

## 四个用户任务与当前入口

产品入口按用户任务划分；H3、Krea 或后续模型家族是执行实现，不决定网站一级导航。沿用 `static/studio/app/mode-registry.js` 的中文名称和稳定 ID，不为术语调整迁移项目或路由。当前图片入口由已有 `image_assets_enabled` 能力控制。

| 用户任务 / 稳定 ID | 保留的现有制作体验 | 真实维护入口（相对仓库根） |
|---|---|---|
| 参考视频换人 / `swap` | 源视频与目标角色整体形象、自动切片及重新准备、逐段提示词、原表演与结果对照、人工审核或自动推进、成片 | `static/studio/modes/swap/workspace.js`；`h3ui/studio_source.py`、`studio_swap_prompts.py`、`segmenter.py` |
| 参考图长视频 / `image_story` | 角色/场景等参考素材、图文分镜、用户目标时长、制作审核与成片；保留当前素材继承与连续声画规则 | `static/studio/modes/image-story/workspace.js`；`h3ui/studio_story.py`、`studio_plan.py`、`studio_inputs.py` |
| 文生视频 / `text_story` | 镜头目录与剧本正文、按镜制作、声音/素材按需展开、审核与合成；带参考时按已有影响确认适配 | `static/studio/modes/text-story/workspace.js`；`h3ui/studio_story.py`、`studio_inputs.py`、`studio_recipes.py` |
| 图片资产创作 / `image_assets`，`kind=image` | 单图、双图、局部重绘/移除、扩图及文生图五工具；任务、画布与指令；候选比较、选定、继续编辑、入库与视频引用 | `static/studio/app/image-workspace-controller.js`；`features/image-canvas/`、`features/image-results/`（均在 `static/studio/`）；`h3ui/image_studio/` |

参考视频换人与参考图长视频是两个用户任务，不能因口语名称接近而合并。图片任务不是视频分镜：继续使用图片任务级设置、运行和输出身份，视频保留项目/片段作用域。

视频继续复用项目会话、唯一命令门、审核和合成服务；图片继续复用现有 `ImageSession`、图片保存/运行服务、GPU 通道与资产库。共用设计组件不要求把两种业务会话强行改成一个。项目、历史作品、固定资产版本与原件保护仍按[资产维护说明](../asset-library-maintenance.md)和[资产架构](../asset-library-architecture.md)执行。

## 扩展分流与固定外壳

同用途的新工作流应进入原模块或原图片工具内的工作流选择；模型换代、节点更多、作者不同均不足以新增一级模块。现有三视频已有 `settings.recipe` 选择及各模式配方列表；图片当前是一个来源图的四编辑分支及派生文生图适配，尚未具备任意工作流选择器。这里规定其后续接入位置，不宣称选择器已经实现。

只有既有模块和工具无法合理表达的独立用户任务，才进入[新增模式流程](../frontend/adding-a-mode.md)。普通兼容模型/LoRA 文件更新走发现、刷新、选择；已有工作流开放字段走参数扩展；新图结构或输入协议走[工作流适配约定](../governance/workflow-evolution-contract.md)。不要把三者都变成新增模式。

保留已认可的导航、工作面组织、主要动作归属、制作参数入口、素材/保存/审核/错误语义、视觉密度和资产体系。工作流适配只调整必要输入、精选参数、提示词格式、局部专用工具、执行计划与结果处理，优先使用既有插槽、公共控件与分组；不能按 ComfyUI 节点排列重做网站。

公共参数行为以[参数与交互契约](../frontend/parameter-and-interaction-contract.md)为准；详细字段、持久化与执行绑定只维护[参数映射](../frontend/parameter-map.md)。图片制作参数已共用 `ui/production-settings.js` 的分类外壳与控件，由 `features/image-settings/index.js` 管理任务临时副本；应用不替换图片画布、素材或外层正文，后续保存仍由图片会话处理。本机文件发现复用视频已有扫描能力，图片远端目录与本机来源分开。图片 V3 布局保留，详见[图片 UI 说明](../frontend/image-workspace-ui.md)；本文件不将代码接入写成用户已经认可的新体验。

## 每个工作流应保留的业务与真实限制

| 目标模块 | 适配必须说明的内容 |
|---|---|
| 参考视频换人 | 角色与源视频输入、正文格式、源切片与单段执行映射、连续上下文、源音轨/生成声音及合成 |
| 参考图长视频 | 多参考与继承是否真实消费、用户分镜与内部任务的映射、首段/新场景输入检查、声画续接 |
| 文生视频 | 文本与适用声音/图片输入、工作流切换影响、内部任务、候选归属和连续性 |
| 图片资产创作 | A/B 图片、逻辑遮罩、蓝色引导与扩边的实际处理，固定运行/输出、候选入库和视频固定版本引用 |

这些是适配责任，不能作为任意工作流已具备全部能力的保证。新选项的能力缺口应由现有编排、前后处理或局部适配补齐；仍不能支持时明确记录该选项的限定，不能静默降低整个模块能力或显示无真实绑定的开关。图片现有蓝色区域是语义引导，区域外可能变化，不能描述为保证只改遮罩内。

## 长视频、审核与来源

用户分镜是创作和审核对象，内部渲染任务是执行对象。继续采用现有故事分镜规则：用户正文按每不超过 15 秒组织，合法帧数与上下文由内部规划处理，不能把每次模型输出都变成额外提示词框。参考视频按源切片及切镜逻辑组织，不机械套用故事分镜规则。

沿用当前分段、队列、人工审核/自动推进、失败恢复与合成。新的工作流须分别核对上下文格式、裁切、参考与音轨策略；不能把当前 H3 的上下文帧数、Latent、分辨率或采样日程推广为通用契约。现有跳舞 8＋4、官方来源及网站 AV/低显存扩展、文戏扩展按各自实际路径保留；编译和拼接成功不证明长链身份、声音或生成质量通过。

官方备选、已有低显存选项、原优化方案及旧项目兼容配方继续保留；新选项不全局替换旧选项。来源图与网站补充适配分开记录；来源快照位于 `h3ui/studio_sources/` 和 `h3ui/image_studio/sources/`，来源存在不等于其任意节点均已接入。不存在官方方案时不得伪称存在。

## 每次交付

改动时在既有任务记录或维护状态说明所属功能/工具、来源与适配 ID、保留的工作区、必要输入和参数、审核/连续性/资产影响、旧项目影响及本次检查范围。代码、相关现行说明、当前状态和必要 AGENTS/PROJECT_GUIDE 路由同批维护，按[上下文维护机制](../governance/context-maintenance.md)完成语义核对、索引刷新及检查。不能只改日期，不能把文档维护留给下一次会话；未授权提交时全部留在同一工作树。
