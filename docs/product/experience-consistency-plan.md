# 时间森林跨模式体验一致性完善方案

2026-09-08，依据用户“功能不同，但应像同一系统中的不同 App 一样拥有一致体验”的要求，承接 [6.3.21复用审查](../ui-code-reuse-audit-20260908.md)。本文件维护目标与实施顺序；本地6.3.25已接入四批共同代码：参数/保存与离开保护、页头/步骤/底栏、候选/播放/结果动作、异步接收与维护收口，不表示现有五模式已经满足全部规则。

## 1. 完善目标

用户在一个模式里学会的操作，应能直接用于其他模式：在哪里添加素材、如何调整参数、修改是否保存、生成期间能做什么、怎样比较和重新生成、选用与收藏有什么区别、返回或离开是否会丢失输入。

复用组件是实现这些目标的手段。共同 CSS 或函数被引用，只能证明实现有共用，不能证明操作感受一致。按用户操作后的结果验收，再检查是否通过公共层实现。

保持时间森林已有纸色、森林绿、字体和工作台风格；计时继续采用用户认可的图片模式呈现。功能内容、工作流、生成默认值与数据结构保持各自业务边界。也不能用“业务不同”解释同名按钮结果不同、无提示丢草稿或同类错误反馈不同。

## 2. 建立共同的操作语言

以下为拟落实的跨模式体验契约。实现时逐入口记录当前行为与目标差异，不直接把规范记为已完成。

| 用户操作 | 所有模式应有的相同预期 | 允许的业务内容差异 |
|---|---|---|
| 返回上一步 | 回到当前项目的前一步，保留已输入的内容与已有结果；不等同于撤销、清空或重新生成 | 前一步的名称与实际内容 |
| 下一步 | 进入下一个业务步骤，发现缺项就定位提示；没有生成含义的按钮不暗中生成 | 确需本地准备时明确写“准备并继续”，不隐藏处理行为 |
| 制作参数 | 同一位置打开同一结构的面板；始终标明作用于哪个项目/片段/图片任务/续写段 | 字段、可用类别、默认值、工作流能力 |
| 取消、关闭、Esc | 放弃本次弹窗尚未应用的修改，保留打开前的项目草稿 | 业务不应改变这三个入口的等价性 |
| 应用 | 把弹窗修改应用到明示对象的编辑草稿并关闭；状态明确显示“有未保存修改”，不提交生成 | 各模式草稿载荷由适配层处理 |
| 保存 | 应用并持久保存所示范围；成功才显示“已保存”并关闭。失败保留编辑、明确原因 | 工作流切换确有下游影响时沿用必要影响确认 |
| 恢复默认 | 只重置当前明示范围的参数临时副本；仍可取消，不清素材/正文/候选 | 默认值来自实际工具/配方；范围标清是否包含模型 |
| 刷新模型 | 只更新目录与来源状态，当前选择和其他输入保留；失败不清空目录 | 本地扫描和需在线的节点同步是两个不同动作 |
| 生成、重新生成 | 使用当前明示对象的有效草稿，先经过原保存/影响确认，再提交一次；追加候选、保留历史；已选结果的影响须明确 | 原三视频重生成取消本段选用并使依赖后续过期，确认说明；图片/接续沿用原选用规则 |
| 选用此结果 | 把该候选确认为当前对象的正式选用结果，立即显示选用状态；不冒充收藏，也不隐藏启动后续工作的副作用 | 接续增加/替换轨道项；视频若还要自动推进，应明确叫“选用并继续制作”等组合动作 |
| 加入资产库 | 收藏当前查看结果，给出“已入库/查看资产”反馈，不改变选用、步骤或开始生成 | 入库记录类型、来源快照各自适配 |
| 移除 | 明确移除的是引用、候选、任务还是轨道项；告知恢复位置，不默默永久删除 | 各业务保护与级联影响必须按实际规则说明 |
| 停止/取消等待 | 明确作用于哪个活动任务；显示请求中、已停止或待确认的真实状态 | 不把“请求停止”立即显示为“已停止”，不做全局引擎中断 |

普通步骤切换尽量不打断用户。离开项目且确有丢失未保存内容风险时，统一使用“保存并离开 / 留在当前 / 放弃本次修改”的处理方式；不在每一次页签和步骤切换时弹确认。已开始的生成继续由全局活动任务列表管理，离开页面不默认停止任务。

上述按钮语义调整是体验改进的一部分，不应只换文案。尤其保存、选用并继续、恢复默认，必须核对真实后端行为和作用域。不能为了显示同一组按钮而提供无实际能力的动作。

## 3. 用户在各模式中都能认出的位置

| 区域 | 共同位置与职责 | 不强行统一的内容 |
|---|---|---|
| 顶部 | 返回项目档案、模式、项目名、状态；制作参数固定右上 | 项目摘要与当前工作流名称 |
| 步骤导航 | 同一高度、选中/禁用/可访问方式；完整表达当前位置 | 不要求相同步数和步骤名 |
| 左侧目录 | 选择当前工作对象、清楚标识当前项；增减/排序操作遵守统一呈现规则 | 图片任务、分镜、视频轨道不同；加号应标明“添加视频”或“新增任务”，不能一律改成导入 |
| 中央工作区 | 当前对象为主，工具、正文、预览围绕对象；状态与时间采用共同的紧凑信息层级 | 图片画布、视频对比、片尾连播等专属工具 |
| 右侧属性区 | 素材入口与信息查看可预期；能分清项目级和当前对象级 | 图片 A/B、声音、输入编号、来源、项目等页签按任务需要提供 |
| 底部操作区 | 左侧返回/保存/保存状态；右侧次动作和当前步骤的主动作，窄屏仍保持顺序与可达 | 主按钮可叫下一步、开始生成、拼接导出；每个局部区域应有清楚主次，避免多个无区分的主按钮竞争 |
| 结果操作区 | 查看/对比靠近预览；选用/重新生成可辨；下载/入库归为收集操作 | 视频审核继续、接续轨道操作通过额外动作表达 |

已有认可的功能分布优先保留。先修正偏离共同区域职责的入口与交互，避免以一致性为由大规模搬动中央画布或重做全部页面。

## 4. 贯穿全过程的体验要求

### 导入

本地与资产库在同一层级选择，导入前能看见目标，例如“导入到当前续写段的参考素材”或“导入到原图 A”。关闭来源选择和取消文件选择不创建任务、不保存其他编辑。进度清楚区分文件传输与服务器处理；接口协议仍可分为普通上传、分块续传和本地收集。

### 参数与保存

五模式共用相同的目录状态、分类导航、LoRA 槽样式、种子提示、错误位置与操作栏。作用对象固定可见，不能因为长参数列表滚动而失去上下文。草稿状态统一为“有未保存修改 / 保存中 / 已保存 / 保存失败”，只依据实际保存结果变化。

运行中可编辑的内容应明确标为下一次生成的草稿；当前运行读取固定快照，编辑不改变正在执行的任务。只锁住确实不能执行的操作，避免把参数修改或查看素材也一并锁死。该规则须尊重各模式现有安全约束，不能从 UI 擅自放宽后端限制。

### 等待、错误与恢复

排队、准备、生成、处理、完成、失败、已取消、待确认各有统一显示规则。业务可以增加子阶段，但不能把排队算成采样进度、把等待确认当作成功或空闲。计时、任务列表、当前工作区的状态应描述同一个任务事实。

错误出现在稳定位置，包含可理解的摘要、真实详情和下一步可执行动作；保留输入与已有候选。选用/入库成功应给出可见状态，而不仅是一闪而过的提示。请求失败但服务端可能已经完成时，先核对或补完成，不能诱导用户重复生成/导入。

### 反复生成与筛选

将“生成→查看→比较→不满意再生成→选用→收藏或继续”视为常态。每次新生成追加候选，当前已选结果与正在查看的候选分别标清；自动展示最新结果不等于自动选用。生成失败仍能查看旧结果。重新生成当前对象与把当前结果作为新输入继续创作，使用不同名称与动作，不能混用“继续编辑”。

本轮不新增全局撤销历史。已有可恢复移除继续使用原回收站和领域保护；如以后增加即时撤销，应复用原恢复 API，另行明确作用范围与失效条件。

## 5. 实现层如何保证一致

形成“公共操作规则 → 完整交互组件 → 模式适配 → 原业务服务”的责任链：

- 公共规则定义同名动作的结果、位置、状态和反馈，作为跨模式验收标准。
- 公共组件同时拥有呈现、焦点、键盘、忙/禁用状态、生命周期及错误插槽。目录/LoRA等共同内部组合也归入公共层，不能只共用最外层框。
- 适配层提供对象、字段、状态映射、可用动作和真实命令；不得重新定义取消/保存等公共行为。确有额外后果时用显式组合动作说明。
- 图片画布、视频分镜、接续轨道、运行恢复和配方编译保留原业务结构。公共层通过接口调用，不能复制数据库和生成逻辑。

已有 production-settings、workbench、run-timing、workspace-actions、error-feedback、reference-assets、candidate-records 优先扩展并补齐调用方。页头/步骤、普通输入选择弹窗等确有空缺时再增加公共入口。新组件必须列出覆盖模式与例外，不以“某模式已接入”推定其他模式已经一致。

## 6. 调整实施顺序：体验闭环优先

| 批次 | 交付 | 完成标准 |
|---|---|---|
| 1：共同操作规则与保存/参数闭环 | 五模式动作对照表；统一参数的取消/默认/应用/保存、保存状态、错误与离开保护。补齐参数内部组合和弹窗生命周期 | 同一套操作脚本在五模式得到相同含义的结果；参数作用域与真实保存正确 |
| 2：共同工作台导航与位置 | 页头、步骤、底栏覆盖；素材导入的来源与目标说明；空态/禁用原因 | 切换模式不需要重新寻找参数、返回、保存、导入和主动作；保持专属编辑区 |
| 3：共同生成与挑选体验 | 候选状态/动作、播放基础能力、重新生成、选用与入库反馈、恢复入口 | 连续多次生成与筛选不丢结果、不混淆查看/选用/收藏；接续轨道和视频审核保持真实行为 |
| 4：异步一致性与维护收口 | 任务状态映射、上传阶段、迟到响应/草稿保护；提取稳定基础机制 | 离开、返回、刷新、失败和重复点击均可预测；公共修改有全调用方回归 |

批次内按小改动逐步落地，先确认现有行为、改公共组件与适配、再完成对应模式检查。每批都横向检查五模式，不能连续只打磨一个模式、最后再让其他模式追赶。更深层媒体工具整理只有实际支撑当前体验修复时才纳入，不让内部重构推迟用户可见改进。

## 7. 用相同的用户任务验收

共同脚本：打开项目 → 选当前对象 → 添加素材（适用时）→ 修改参数 → 取消后重开 → 恢复默认后取消 → 应用 → 保存 → 模拟生成/处理 → 查看与比较 → 再次生成 → 选用 → 入库 → 切换项目再回来。

追加异常脚本：输入不完整、模型刷新失败、保存冲突、关闭弹窗后迟到响应、双击生成、离开项目、移除/恢复、排队取消、停止尚未确认。每项记录预期/实际、所属公共组件、业务适配差异和证据；缺功能不能靠隐藏按钮冒充通过。

验收分开记录：

1. 视觉：同屏对照字号、密度、对齐、留白、层级、忙/禁用/选中状态，检查常用宽屏和窄屏；不以无溢出代替协调性验收。
2. 交互：同名操作的结果、反馈位置、返回/取消和草稿保留一致。由业务不同引起的额外后果必须明确说明。
3. 数据：真实隔离 API、保存重开、固定快照/离线绑定、原结果与资产保护。
4. 用户体验：用户在实际日常创作中确认操作感是否一致；自动检查不能代替这个判断。

开发检查使用临时数据库、合成素材和受控响应，不运行 ComfyUI 或真实生成。纯 UI/UX改进不改变配方、默认生成语义、历史数据和工作流文件；不自动安装、提交、推送或发布。
