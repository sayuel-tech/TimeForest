# 时间森林公共界面与视频拼接优化方案

状态：原方案保留为实施依据。用户随后授权执行，本地6.3.13已完成公共参数外壳、步骤底栏、拼接导入及续接参考素材接入；下文问题和未来式属于规划时记录。现行组件归属见[公共界面](../frontend/shared-ui.md)，实际检查与尚待真实生成范围见[维护基线](../maintenance-baseline.md)。未更新GitHub。

## 1. 优化目标

五个模式的共同界面由共同组件直接生成：尺寸、排版、间距、分组、按钮层级、焦点和窄屏行为只维护一份。模式提供自己的字段、能力、数据作用域和业务操作。针对图片画布、视频审核、拼接顺序、AI续接等不同任务，保留独立工作区内容和交互。

保持已认可的纸色、森林绿、标题、面板和控件风格。公共制作参数以原三个视频模式与已认可图片模式的呈现为依据；计时继续使用已统一的图片模式呈现。不新建视觉体系，不把五模式强行合成同一种业务流程。

## 2. 实际差异与原因

| 用户反馈 | 已确认源码事实 | 修正方向 |
|---|---|---|
| 两种导入方式分散，位置不当 | 拼接workspace将本地导入放在左侧加号/中间空态，库选择放在左目录底部；右侧只有来源、项目 | 第一步右侧增加导入页，同组呈现两种来源 |
| 下一步位置突兀 | 拼接footer有三个直接子项，私有CSS用space-between分配；下一步因此位于中间，直接导出占最右侧 | 统一操作栏左右分区，右侧固定次动作在左、主动作在右 |
| 添加续接后缺少素材区 | add_extension未存参考素材；compile_tail将assets=[]、asset_mode=none传给原编译器 | 补齐续写段参考素材业务，从选择到实际节点绑定；不能只加素材卡片 |
| 制作参数样式不一致 | 公共productionSettingsMarkup已存在，但workbench.css大量规则依赖#settings-content；拼接使用data-assembly-settings-root，未命中弹窗宽度、标题、间距及底部样式。字段网格、LoRA布局、操作按钮又由各调用方拼装 | 公共组件拥有根容器、字段布局、操作栏、样式与生命周期，消除调用方隐式ID约定 |
| 复用之后仍各改各的 | 当前复用以HTML片段和基础控件为主；完整弹窗与部分布局规则仍散落于模式/features | 将复用边界上移到完整界面组件，同时保留业务适配 |

上述为源码诊断；本轮没有复现用户当前浏览器的计算样式。现有61项Python、34项Node、4组浏览器通过只说明上轮检查范围，未覆盖这些设计要求，不能视为本方案验收通过。

## 3. 视频拼接的具体调整

### 第一步：视频与排序

- 右侧页签为“导入 / 来源 / 项目”。首次进入空项目选中导入；已有项目可记忆当前页签。
- 导入页同组放置“从资产库选择”和“导入本地视频”，同等级按钮、相同尺寸和间距，宽度允许时并排，窄屏上下排列。二者均追加到当前视频序列，支持已有的多选。
- 左侧只负责视频目录、排序、选择与移除。若保留加号，加号只打开右侧导入页，不直接唤起本地文件选择。中央空态引导打开导入页，不重复放一套文件选择入口。
- 来源页显示当前视频属性与固定版本；项目页保留项目名称和输出摘要，输出参数仍在顶部制作参数。
- 底部操作栏左侧为返回、保存及保存状态等辅助操作；右侧为“直接拼接导出”“下一步：续接与挑选”，下一步是最右侧主按钮。沿用其他工作区的按钮高度、间距和底栏底色。
- “直接拼接导出”保持当前跳转成片页的语义；最终执行由成片页“开始拼接”触发，不借位置调整新增自动处理。没有有效视频时，两个前进动作均说明原因并禁用。

布局示意（表达位置，不代表新视觉设计）：

```text
视频目录        当前视频预览、使用范围        导入 | 来源 | 项目
                                            从资产库选择  导入本地视频

返回 / 保存 / 保存状态          直接拼接导出   下一步：续接与挑选
```

### 第二步：续接与挑选

选中或添加续写段后，右侧默认进入“素材”。页签按当前业务配置为“素材 / 声音 / 输入 / 来源 / 项目”；窄宽度采用公共页签溢出处理，不压缩为难点选的小按钮。无续写段时提示先添加，并保留来源与项目信息。

素材页沿用参考图长视频现有卡片和导入布局：本地图片、本地声音、从资产库选择，下面是本段参考素材列表。支持角色、服装、场景、色系和参考声音等现有用途、角色标记、预览与移除本段引用。素材资料PROMPT仍不自动插入正文。

“声音”呈现确实绑定的参考声音用途及续接声音摘要；生成声音/续接静音的参数仍由制作参数单一入口编辑，不在侧栏复制同字段。“输入”展示真实Picture/Audio编号、角色对应和尾部上下文来源，编号取实际有效顺序。对未接入的结构化声音/对白编排不能仅复制原模式表单。

明确两条输入通路：

| 输入 | 作用 | 约束 |
|---|---|---|
| 原视频或前一段已选结果的尾部声画 | 延续动作、镜头和声音 | 保留既有22帧视频与对齐音频准备及裁头逻辑，不占Picture/Audio素材编号 |
| 用户为当前续写段指定的图片和声音 | 角色、场景、服装、色系、音色等生成参考 | 按所选工作流实际参考输入绑定，不能代替尾部上下文 |

现有studio_inputs与Recipes.compile已经有图片/音频清单和加载链，两种续接配方可沿该公共链适配。实现时仍要逐配方离线核对，不能仅凭原参考图模式存在就宣称已接通。恢复目前过滤掉、将被实际使用的reference_size等参考参数，并更新唯一参数映射。

素材属于当前续写段。首个新增段默认无额外参考，保留原无素材续接行为；继续续接时提供明确的“沿用上一续写段素材”操作，绑定固定版本，不悄悄沿用其他视频组。已保存旧项目缺字段时按空素材读取，不批量迁移。

完整接入包括：本地上传/库版本选择 → 段内引用与用途 → 草稿保存 → 输入编号和预检 → 固定运行快照 → 真实加载节点及条件输入 → 结果来源记录。运行快照保存文件哈希、库版本、用途、角色、顺序和当次参数。后续改素材只影响下一次生成；已有候选不被重写。选用新候选后沿用现有下游失效规则。移除引用不删素材文件、资产或历史运行。

## 4. 公共界面组件的责任划分

在现有Flask和原生ES Modules基础上做局部抽取，不更换框架，不合并五模式的数据模型、调度和保存事务。

| 公共模块 | 共同组件负责 | 模式适配负责 |
|---|---|---|
| 制作参数完整弹窗 | 根容器与专用class、宽高、标题、目录区、摘要槽、分类导航、字段网格、LoRA槽布局、错误区、操作栏、窄屏、焦点、关闭及异步失效处理 | 字段定义/条件/分组标题、当前值、默认值、模型目录来源、校验、应用和保存回调、工作流切换影响 |
| 步骤操作栏 | 左辅助区、右动作组、主次顺序、粘底、换行、禁用/忙状态和按钮视觉 | 步骤名称、可用动作、前进条件、保存/生成/导出动作 |
| 导入选项组 | 并列选择样式、文件选择控件、反馈与空态 | 允许媒体类型、多选、导入到项目视频还是段内参考、上传与取消处理 |
| 素材卡片与列表 | 缩略图/音频预览、标题和用途、管理菜单、长名称、空态 | 固定库版本、角色/用途、引用规则、移除权限与保存 |
| 工作区侧栏 | propertyTabs、可达的页签/滚动布局、共同间距和宽度 | 每步有哪些页签、默认页、当前编辑对象和面板内容 |
| 状态、计时、错误 | 继续使用run-timing和error-feedback现有公共实现 | 业务状态、真实时间来源和错误内容 |

制作参数继续扩展ui/production-settings.js；将它对应的样式归入公共专用样式文件（拟新增styles/production-settings.css），样式以组件根class定位，不依赖调用方创建某个ID。字段组统一接收布局描述；只有画布、蒙版等特殊编辑器通过插槽提供内容。

完整弹窗由公共入口创建并销毁，调用方不再自己调用modal后补外壳。公共入口保留每次打开的实例标识，统一处理Esc、关闭、取消、旧请求返回、切页和销毁。后台请求与事务仍由适配器执行，不把项目保存逻辑塞进展示组件。

共同语义明确：取消丢弃弹窗副本；恢复默认只修改适用字段的副本；应用写入对应草稿；保存通过业务原保存门持久化。按钮位置和命名遵守共同约定；不同模式是否提供独立保存，按实际能力配置，不在纯视觉调整中强加新的保存行为。图片仍不因开关弹窗上传遮罩或重建画布。

三个原视频模式共用workflow-settings适配，图片使用image-settings适配，拼接使用assembly-settings适配。三类适配都调用同一完整弹窗；将来修改圆角、分类栏宽度或按钮间距，只改公共组件。参数数量、类别和默认值仍由各工作流给出，不把图片和视频参数清单统一成一张大表。

## 5. 实施顺序与检查门槛

| 阶段 | 工作与交付 | 必须检查 |
|---|---|---|
| P1 公共外壳 | 抽取完整参数弹窗和步骤操作栏；迁移三个视频共享适配、图片和拼接调用；以现有认可样式为基准 | 五模式实际渲染的弹窗宽度、标题、网格、滚动、按钮对齐；取消/默认/应用/保存及异步关闭行为 |
| P2 拼接第一步 | 右侧导入页、同级来源选择、空态引导和右侧动作组 | 两种导入归属相同；多选取消无副作用；主按钮最右、纯导出不误生成；零片段与忙状态 |
| P3 续接素材贯通 | 抽取复用素材卡片/导入选项；续写段引用、后端保存/快照/预检、双配方图绑定、第二步侧栏 | 无素材/图片/声音/混合输入、固定版本、正确编号、参考与尾部同时存在、双配方切换、旧候选保护 |
| P4 联合验收与文档 | 统一检查五模式、拼接完整流程及旧项目；同步使用说明、参数映射、地图、维护基线与AGENTS | 隔离真实API→浏览器→保存→编译；相关原功能回归；明确仍待用户生成体验 |

每阶段代码与相关文档同批完成；不能先登记“已统一”，把实际迁移留给以后。P1优先解决共同呈现，P3是必要的业务补齐，不能以P1/P2的布局完成代替整个修复完成。

视觉检查覆盖1280×720、1920宽屏及760窄屏，同一组五模式样例核对空、满、忙、错误状态。除了无横向溢出，还检查公共根class是否实际生效、主要操作位置、字段网格、弹窗底栏可见性、长模型名和页签可达性；截图并排检查协调度。DOM文本断言不能代替视觉验收。

功能检查只使用临时项目、合成素材、假模型目录和引擎替身。素材引用变化、段切换、刷新、移除/恢复、重复生成与入库的证据必须包含持久化结果和实际编译图，不能只截按钮。旧项目无素材字段保持可打开、可普通拼接、可无参考续接；不改原工作流文件、默认采样、生产数据或数据库结构。

真实AI续接的角色遵循、动作、声音、接缝和长链效果由后续用户生成验证。本方案不自动授权运行ComfyUI、安装环境、提交、发布或GitHub同步。

## 6. 维护约束与完成标准

每个共同组件登记唯一呈现入口、唯一样式归属、调用模式和业务适配位置。新模式必须通过公共入口获得完整外壳，不复制HTML/CSS，不靠私有选择器补齐共同布局。只改美观度时，修改共同层并核对全部调用方；只有明确业务差异才新增插槽或适配，不修改原模式私有文件来借功能。

完成时用户应能在右侧同级选择两种视频来源；最右侧自然进入下一步；添加续接立即找到本段参考素材；五模式制作参数有一致的外观和关闭/草稿语义。开发者修改一次共同呈现即可更新全部调用模式，模式专属业务和历史结果保持。

实现定位：前端ui/production-settings.js、ui/workbench.js、features/workflow-settings、features/image-settings、features/assets、features/prompts/authoring.js、modes/video-assembly；样式styles/workbench.css与相关组件样式。后端h3ui/video_assembly、studio_inputs、studio_recipes及既有资产适配入口。目录均相对仓库根或static/studio，详见[项目地图](../../PROJECT_GUIDE.md)。
