# 时间森林统一提示词管理：持续开发执行方案

编制日期：2026-09-09。方案版本：3（按真实工作流及上游模型来源分类，保存项目时自动收录）。依据本地6.3.31实际代码与用户最新要求。

**当前状态：2026-09-09本地6.3.32已完成P1～P5本期范围。** 本文是后续实施与接续的唯一任务账本。网站现状仍以[维护基线](../maintenance-baseline.md)为准；未来剧本创作模式的具体业务方案由用户另行确定。

## 1. 目标与完成范围

建立“独立提示词库 → 公共编辑/选择工具 → 五模式适配 → 原保存与生成服务”的共同体系。用户在工作区保存提示词后自动收录分类，随后可收藏好用的内容、跨项目查找复用、找回某次生成实际使用的文字。新增剧本模式与本地/云端LLM以后接同一套管理接口，不重建第二个库。

本期完成：

- 全局提示词库：视频／图片／剧本一级用途、各用途下可管理的模型分支，以及提示词新建、搜索、标签、收藏、编辑、复制、固定版本、可恢复移除。
- 五模式编辑区：同一工具栏与弹窗，选择使用、收藏、复制、展开编辑；原项目保存成功后自动收录分类，无需另点入库。
- 现有结构化视频字段组合的收藏与显式应用；普通文字与完整正文的用途区分。
- 生成记录中的实际提示词查看、复制、收藏、用于草稿，以及可核实来源跳转。
- 当前有效输入编号检查、适用范围说明、旧后台能力提示。
- 可扩展内容类型、版本、来源和公共接口；记录未来剧本/LLM的接入约定。

本期不做：剧本创作页面、章节/场次/对白业务模型、LLM客户端或服务适配、模型安装/下载、云端调用、AI改写/评分/自动试参、提示词市场、复杂变量模板引擎、逐字编辑历史、全站重构。普通开发不授权提交、推送、tag或Release。

本方案不修改现有工作流、模型选择和默认生成语义；不批量迁移现有项目/资产数据库，不扫描全部历史作品自动入库。新库独立存储，旧项目按需兼容。

## 3. 产品概念与数据边界

| 概念 | 所属位置 | 规则 |
|---|---|---|
| 当前创作提示词 | 原项目/片段/图片任务/续写段草稿 | 原保存门持久化；库操作不能代替项目保存 |
| 可复用提示词 | 新提示词库 | 保存项目时自动收录创作记录；主动新建/收藏/编辑副本和复用 |
| 本次实际提示词 | 原执行快照/生成记录 | 只读；可另存，不改历史 |
| 资产资料PROMPT | 既有资产资料 | 不自动进入生成正文；主动复制或另存时标资料来源 |
| 剧本作品 | 未来剧本项目 | 不存成提示词库条目，除非用户主动收藏某段 |
| LLM会话与候选 | 未来辅助创作模块 | 与库关联，但不作为库的内部存储或自动覆盖当前正文 |

“可复用”不等于“跨模式原样就有效”。内容类型、目标用途、工作流适配和输入编号分别表达；推荐适用范围不是模型兼容认证。

## 4. 统一UI与操作约定

### 4.1 全局库与编辑区

增加全局“提示词库”工具入口，和项目档案/资产库同属工具导航；不进入创作模式卡片。使用现有导航尺度和窄屏规则，若导航拥挤则复用/扩展公共工具菜单，不为单页另造导航样式。

库页面按“用途 → 模型 → 选择提示词并编辑”组织。左侧为视频／图片／剧本与各自模型分支，中间为当前分支提示词列表，右侧为选中条目的详情/编辑；窄屏沿公共响应式规则改为逐层进入，不挤出三个固定列。默认列表显示名称、正文摘要、标签、最近修改与可选来源；不为文本套用大幅媒体卡片。搜索/收藏默认限定当前分类，并可明确切换为全库；筛选面包屑持续显示，不让用户误以为条目丢失。

各模式原正文位置不变，统一工具栏：“从提示词库选择 / 收藏 / 复制 / 展开编辑”。正常保存项目即自动收录，不再以“保存到提示词库”作为必经动作。收藏是便于以后筛选的标记，不等于首次收录；已保存内容可直接收藏，未保存内容可明确“另存并收藏当前文字”而不触发项目保存。业务名称可仍叫镜头与表演、编辑指令、后续画面与声音描述。工具缺能力时说明原因，不显示无效假按钮。

### 4.2 分类管理：用途 → 模型 → 编辑

这是用户本次明确的主导航，不再只靠标签筛选实现。第一层固定显示“视频、图片、剧本”，对应稳定用途标识video/image/script；本期不提供删除或任意改名这三个系统用途的操作。未来新增用途由业务扩展明确接入，不写死在生成服务中。

第二层按提示词规则所属的模型家族分类：视频 → 通用 / H3 / Wan等；图片 → 通用 / Krea2 / 未来接入的家族；剧本 → 通用 / 未来接入的LLM家族。当前工作流的视频归H3，图片五工具归Krea2。Wan是用户举例的未来分支，目录条目可管理不代表已经支持Wan生成。每个用途必须有明确的“通用”分支。

“参考视频换人、参考图长视频、文生视频、视频接续”是视频提示词的用途标签/筛选项，不再各自建一级库。图片五工具也作为适用工具筛选。第三步是选择某条提示词进入编辑，不再强行增加固定的工作流目录层级。

模型分支表示共享提示词skill/规则的家族，不按底模文件、量化精度、微调版本、LoRA或跳舞/官方配方拆分。具体版本可作为标签和来源信息。家族稳定标识与显示名分离，显示名修改不破坏自动分类；未来按上游基础模型归属扩展家族；同家族的任务协议、输入能力与专用触发词作为适配信息，不因此拆成新的家族。这里的skill是模型提示词约定，不是自动执行用户文本或调用本机Agent技能。自定义家族支持增改排序和回收；通用以及工作流当前依赖的内置家族不可删除或移到别的用途，避免下一次保存无处归类。

“通用”表示用户有意整理为跨模型的创作表达，不等于无法识别或全部模型已经兼容。库内独立新建普通文字时可默认当前用途的通用分支。旧数据或自定义工作流无法识别家族时，保留空家族与“待归类”管理筛选，不冒充通用、不丢内容、不阻止原项目保存；已声明家族的当前工作流不应要求用户手动分类。待归类是异常收纳状态，不是新的模型家族。

分类操作规则：

- 用户主要在创作工作区写提示词：保存时从同一份已确认的工作流/参数快照自动记录用途与提示词家族，不要求额外选择分类。库内独立新建才沿当前浏览路径填写，常规保存不弹分类向导。
- 提供“移动到分类”和“另存到另一模型”。第一版每条记录有一个明确的主分类路径，避免多处目录编辑同一记录却无提示。
- 移动只改组织归属，不改变正文、既有内容版本或项目引用；跨用途移动检查内容格式，无法在目标用途编辑的组合说明原因，不丢字段或强制转纯文本。
- 另存到另一模型创建独立条目，保留来源版本关联，便于分别修改模型写法。明确显示是副本；不暗中同步多个分支的内容。
- 移除模型分支时保留条目和分支身份，归入库内分类回收视图；条目不再出现在正常分类列表。给出受影响数量和“移到其他分支后移除”的选择，绝不级联永久删除正文。恢复分支不复活原本单独移除的条目。
- 正在被移除分支中的条目仍可从回收视图查看、移动；项目已复制的文字和固定版本引用保持可读。跨分支移动和重命名沿同一revision冲突保护。
- “剧本”分类及其普通文本收藏/编辑本期可用，不依赖剧本工作区或LLM连接完成；尚未接入的生成按钮不显示。保存创作指令不等于已经实现剧本创作模式。

工作区打开选择器时默认定位当前用途的模型家族，并提供并列的“通用”快捷入口。默认模型列表不混入通用条目却不标来源；切到通用或全用途搜索时明确显示当前位置。分类选择只决定浏览/收藏位置，不自动改变工作区模型、工作流或正文方式。跨模型使用沿现有适用范围/编号检查，不以目录名直接禁止复制普通文本，也不能冒充兼容。

### 4.3 核对工作流与模型来源，再自动分类

家族归属是调查结论，不能用网站现有模式名或人为新增的声明代替调查。先沿实际编译路径确认承担生成任务的主模型及其加载/条件节点，再用完整模型名查作者模型卡、原始仓库及基础模型关系，追溯量化、微调、合并版本的上游家族。编码器、VAE、放大模型和LoRA分别记录组件角色，不因文件名出现在图里就把它当作主模型家族。

本地核对入口：`h3ui/studio_recipes.py`中的RECIPES及主模型常量、`h3ui/studio_sources/{dance,official_r2v,official_t2v,wenxi}.json`、`h3ui/image_studio/compiler.py`及其`sources/krea-edit.json`、`h3ui/video_assembly/compiler.py`。仅出现在源文件目录或模型缓存、没有接入当前配方的图/文件，不当成当前可选工作流。

图片源图的Krea2编辑/编码节点与上述主模型互相印证；Qwen3VL是文本编码组件，Qwen-image VAE是解码组件，[上游文件目录](https://huggingface.co/Comfy-Org/Krea-2)也明确区分这些角色，因此不能据此把图片提示词归入Qwen家族。同理，视频图中的编码器或空间放大组件不改变H3生成主模型的归属。

实施方式：

1. 在维护期建立可复查的模型来源关系，记录实际主模型识别依据、上游仓库、基础家族及工作流角色。完整文件名是查找线索，作者来源与图中角色才是归属证据；不只靠名称包含某个单词猜测。
2. 将已核实关系作为公共目录的家族元数据（如`prompt_family_id`）供保存链读取。它是调查结果的存储形式，不能先写死“所有视频都是H3”再当成证据。现有编译器内部的模型能力判别仍保留原用途，不直接当提示词分类表。
3. 保存时读取本次实际选用的主模型及工作流上下文，匹配已核实的来源关系；新家族按真实归属扩展。不能在用户更换主模型后仍无条件使用配方默认模型的分类。具有可靠架构/来源元数据的同家族新版本可复用家族关系，无法确认的进入待归类，不因分类缺失禁止选择模型或保存项目。
4. 正常保存离线完成，不为每次保存联网查询、不上传用户提示词。后续引入未知工作流或模型时，维护者按同一调查步骤补充关系；这不是模型使用白名单，也不要求用户日常放文件、刷新、选择前登记或获得生成认证。
5. 家族目录共享基本提示词规范；文生、参考、编辑、声音字段和LoRA专用触发词仍按具体工具/工作流能力保留，不宣称同目录的文字在所有任务里都能原样适用。以后剧本模式也按实际LLM上游家族分类，本地/云端是连接方式，不是模型家族。

上述关系已由families.py及identify接口提供公共元数据，自动收录读取同次保存的实际模型；实现见现行说明。维护者接入时复核当前代码与作者来源变化，不按这份快照覆盖用户后续选择。

保存时使用对应目标的实际作用域：原视频为本次保存片段及有效配方，图片为当前任务工具，接续为当前续写段配方；生成记录收藏则优先读取生成时的工作流记录，不能用项目后来切换的模型归类。改变模型或配方但正文未变时也要保存新的使用上下文，不能只根据文本变化判断模型未变。

条目的管理分类与制作时模型来源分开：用户可主动整理到“通用”或另存到别的家族，但原生成记录的H3/Krea2事实不改。具体文件版本保留为来源字段，后续提示词家族规则升级也不重写旧正文或运行记录。

**用户已确认：保存项目时自动收录并分类。** 这替代V1/V2以主动收藏作为主要入库入口的设计。收录源为本次真实保存成功的内容与工作流上下文；不收录每个按键、未应用的弹窗内容或失败的项目保存。生成前沿原保存门保存成功，同样触发这一行为，不再做一个生成专属旁路。

自动记录规则：

- 非空有效提示词按项目、目标对象、内容范围及模型家族确定稳定自动记录身份；原视频每片段、图片每任务、接续每续写段分别归属，不能把整个项目混成一条正文。换人项目默认正文与片段覆盖分别标示；纯继承且无独立内容时记录继承关系，不重复创建相同正文。
- 同一目标/家族内容未变，重复保存不新增条目或版本。只改项目名称、模型量化版本等，不制造提示词正文新版本；记录本次正确的保存上下文即可。
- 同一目标/家族正文有变化，更新该自动记录并保留内容版本；不是每次新增一张重复卡片。跨家族则建立对应家族的使用记录，保留旧家族记录和旧生成事实。
- 自动记录与用户手工模板用record_kind区分，仍在同一用途/模型树中管理，可按“全部 / 创作记录 / 我的模板 / 收藏”筛选。不要建立另一个对用户隔离的提示词库。
- 自动记录正文对应项目保存事实，因此库里“编辑”打开副本并明确“另存为模板”；不倒写项目、不改历史。用户可编辑自己的模板、管理名称/标签/收藏/分类，后续项目保存不得覆盖这些人工整理。模板使用到项目后仍生成该项目自己的创作记录。
- 实际模型来源与管理分类分开。已主动移动到通用的条目再次保存，不被自动分类搬回；按已知来源身份更新，不按当前目录寻找或重复建条目。用户单独移除的自动记录不因普通保存悄悄恢复；已移除期间的新版本继续归同一回收记录，恢复后可见，避免同内容反复回到正常列表。
- 项目保存失败：不产生自动记录。项目保存成功但库写入失败：项目仍显示已保存，额外显示“提示词未收录，可重试”；重试只补记该次已保存快照，不重新保存项目、不生成、不读取此刻已修改的输入。结合原保存事实/可选凭据提供幂等补记，不自建后台全历史扫描或大型队列。
- 用户一次保存多个实际编辑对象时仅对这些对象的有效内容补记；不借一次保存导入项目全部历史运行或整个资产库。


### 4.4 动作的精确定义

| 动作 | 行为 |
|---|---|
| 打开库/预览 | 只读，不保存项目、不改变当前文字或选用结果 |
| 使用普通文本 | 明示目标；替换正文，或在同一普通文本字段中插入选区/光标位置。记录打开前的选区，无法确定位置时不擅自插入 |
| 覆盖已有内容 | 明示被替换字段和范围，确认后一次写入当前草稿；取消保留原状 |
| 使用字段组合 | 列出将写入的字段及缺失字段；只应用明确选择的部分，不自动清空其他字段；不提供盲目追加整个组合 |
| 展开编辑 | 使用临时副本，取消/关闭/Esc等价；应用回当前草稿，不自动保存项目 |
| 收藏/另存模板 | 保存项目已自动收录；收藏是标记。未保存文字如需独立收藏则明确另存，自动带入用途/家族，不代替项目保存 |
| 更新库条目 | 项目保存更新所属自动创作记录；库内编辑自动记录另存为模板。手工模板仅经用户编辑更新，不被项目自动保存覆盖 |
| 保存项目 | 继续原保存门与影响确认，成功后自动收录并分类；项目失败保留草稿，库收录失败单独提示并可补记，不误报项目未保存 |
| 查看生成时提示词 | 只读且定位具体运行/输出；复制、另存或用于草稿均为独立动作 |
| 移除/恢复库条目 | 软移除；库内回收视图复用既有回收交互样式，恢复不应用到项目。暂不重排资产库已有三类回收入口 |

库弹窗期间切换对象/关闭后，迟到响应不能应用到新对象。原三视频运行中的独立草稿规则、图片任务保护、接续锁定与revision校验继续生效。

## 5. 最小数据模型与存储

建议新增 `h3ui/prompt_library/` 独立服务和SQLite文件，沿现有配置路径解析方式配置 `prompt_library_dir`；默认采用应用数据根下的独立子目录，实施时核对仓库分发排除规则。新建自己的表不等于迁移项目或资产表。提示词数据与备份不进入源码发布包。

| 对象 | 最小内容 |
|---|---|
| 一级用途 | 稳定id：video/image/script、显示名、排序；本期为系统分类 |
| 模型分支 | 稳定id、purpose_id、名称、排序、revision、稳定prompt_family_id、system标记、deleted_at；不含连接配置，不绑定某个本机文件路径 |
| 条目 | 稳定id、title、content_type、purpose_id、model_branch_id（通用为明确分支，空表示待归类）、record_kind（创作记录/手工模板）、稳定来源目标键、适用模式/工具标记、tags、favorite、current_version、revision、created_at、updated_at、deleted_at |
| 不可变内容版本 | version_id、schema_version、content（正文或已定义字段组合）、可选source（含制作时家族/配方/模型文件）、created_at |
| 自动收录上下文 | 已保存项目revision/快照身份、目标/字段范围、prompt_family_id、工作流及必要文件版本信息、收录凭据；与手工管理分类分开 |
| 使用来源标记 | entry_id、version_id、应用的字段与目标、应用内容摘要；附着于项目既有可选元数据，随原保存门提交 |

规则：

- 第一版覆盖自动创作记录与手工模板的普通文本、完整生成正文、现有视频字段组合；不要提前制造剧本字段。content_type和用途由注册/适配表扩展，不写死只有五模式。
- 当前纯文本按原文保存：不自动翻译、润色、补禁止项或替换编号。目标字符限制沿用实际保存限制，超限提示并保留输入，不静默截断。
- 模型分支必须属于条目所选一级用途，后端验证归属。使用稳定分类ID，不用显示名作外键；重命名不破坏链接。
- 内容或制作相关结构变化才产生新内容版本；分类移动、重命名、收藏、标签等管理修改不制造正文历史。所有写入有revision冲突保护；删除/恢复不修改旧内容。
- 使用库内容是复制到目标草稿，附可追溯版本信息，不是运行时动态读取库最新版。库更新/移除不改变已有项目。
- 用户手改后，来源仍可显示“基于某版本，已修改”，不能声称与原版完全一致。字段被替换/清空时更新对应来源标记；不得保留误导性的旧绑定。
- 老项目没有来源标记时正常读取，不批量回填。必须核对原保存字段白名单，不能加前端字段却被后台悄悄丢弃。
- source可记录来源类别、项目/任务/片段/运行/输出/固定资产版本身份。项目不可用时保留已知名称和缺失状态；不按同名项目补链接。
- 参数建议与正文分开；不把密钥、服务地址或生成环境配置塞进正文版本。现有提示词库不承担模型连接配置。
- 可提供显式另存旧版本；不做每键快照、分支合并、逐字diff或复杂历史恢复系统。

条目新建成功前禁止重复点击；结果不明先核对而非盲目重试创建。按现有模式使用请求标识/幂等回执处理必要的新建防重，不自建大型任务调度器。

## 6. 公共模块与接口职责

以下路径和接口是拟新增的实现契约，阶段P1核对后确定；变更时同步本文，不将目录存在当成功能完成。

| 层 | 建议入口 | 职责 |
|---|---|---|
| 库后端 | `h3ui/prompt_library/{store,service,routes}.py` | 用途/提示词家族映射、模型分支、条目、固定版本、筛选、revision、移除恢复；独立于生成器 |
| 公共来源解析 | `h3ui/prompt_library/records.py`（按需要新增） | 从指定执行记录提取真实文字/字段及来源；不扫描全库、不重跑编译或生成来恢复历史 |
| 库工具页 | `static/studio/pages/prompt-library/` | 分类树、列表、详情、编辑、条目与分支回收状态 |
| 公共操作 | `static/studio/features/prompt-library/` | API客户端、选择预览、收藏、应用意图；复用scopedModal和异步生命周期 |
| 公共编辑呈现 | `static/studio/ui/prompt-editor.js` | 工具栏、展开编辑、复制反馈和样式；不拥有模式保存 |
| 模式适配 | 各现有features/modes入口 | 目标、可写字段、格式、当前输入、原dirty/save与记录读取 |

API建议：`/api/v5/prompt-library/catalog`（用途及能力）、`/model-branches`（模型分支管理）、`/entries`、`/entries/<id>`、`/entries/<id>/versions/<version>`，以及显式移除/恢复动作。catalog声明支持的内容格式、操作及能力版本；旧后台缺接口时公共组件明确报错，不呈现一个可保存的空库。

公共适配至少提供：当前目标身份、可写字段/格式、读取草稿、应用字段patch、标记dirty、打开前的编辑代次、实际输入清单能力。公共层发出用户确认的意图，由原业务适配提交，不能直接修改任意project字段。

不新增一套通用提示词编译器。普通视频仍走studio_prompts，换人走studio_swap_prompts，图片/接续沿原compiler；共享层管理内容，不决定生成语义。

## 7. 五模式的具体适配

| 模式 | 作用范围 | 必须保留的差异 |
|---|---|---|
| 参考视频换人 | 项目默认或当前片段，必须明示 | 模板/自定义/继承三种实际关系；补充说明与完整正文分别收藏。套用完整正文若需要切换方式，明确显示“改为本段自定义完整正文”，经确认后执行；不隐式升级模板或改其他片段 |
| 参考图长视频 | 当前片段 | structured/full；正文及声音等可保存组合。插入单字段不改变正文方式 |
| 文生视频 | 当前片段 | 保留原分镜与时长规则；不能把结构正文放入structured字段后再次包裹却不说明 |
| 图片资产创作 | 当前编辑任务 | 按五工具显示用途；图片普通文字不附加视频声音字段，不切换工具、不触碰画布/标注 |
| 视频接续 | 当前续写段 | 只改该段草稿，不变成父段/项目全局正文；不改轨道、已选候选或后继运行快照 |

字段组合使用白名单：prompt、staging、beats、ending、voice、soundscape、music等只在真实模式/正文方式支持时提供。speaker_order等编号字段必须结合实际声音清单确认，不能把来源项目编号当跨项目通用值。

库中带有 `<Picture 1>`、`<Audio 1>`、`<Video 1>`、`<Subject 1>` 或S发声编号的内容，复用当前有效输入能力检查；这些体系不互相等价。缺少引用时显示问题并保留用户文字，不自动上传素材、换编号或切配方；不以词法检查宣称人物对应正确。最终生成仍经原真实校验。

## 8. 为剧本模式与LLM预留什么

本期完成的是下列边界与扩展点，不实现空的Provider框架或未设计的剧本模型。

- 库服务不依赖ComfyUI、具体LLM厂商或五模式枚举。新增调用方可读取固定版本，使用同一选择/收藏/来源接口。
- 将来允许增加剧本创作指令、角色设定、系统指令/用户指令组合等内容类型。现在只定义schema_version与类型扩展机制，不显示尚不可用的菜单。
- 剧本项目拥有作品和会话；LLM模块拥有请求、候选与模型配置；提示词库只拥有可复用内容。三者通过稳定身份关联。
- 未来LLM输入由用户选择的固定提示词版本、指定项目上下文和本次要求组成。只读库不等于授权向云端发送；不得默认发送全库、全部资产或整个项目。
- 未来LLM结果先是候选；采用才进入明示对象的草稿。另存到提示词库与采用分开，不静默覆盖，不自动生成视频。
- 未来记录本次实际使用的提示词版本、内容、所选模型及必要来源；密钥/连接凭据归独立配置，不写进可分享提示词。
- 跨模块传递普通文本或结构内容使用可识别格式；未知类型可以安全显示原文/说明不支持，不能解释执行其中脚本、表达式或工具调用。

剧本页结构、剧本与分镜转换、LLM协议/供应商、流式响应、计费、上下文长度、多轮记忆、系统指令优先级和媒体能力，等待用户未来方案。不要为了“提前准备”自行确定这些业务。

## 9. 分阶段任务与完成标准

一次获准执行本方案后按依赖推进，不在每个阶段重复索要许可。需要跨会话时，更新第11节账本；用户说“继续”先接续未完成项，不重做以前阶段。

### P0：方案与维护接入（已完成）

任务：核对现状、明确范围、建立本文与维护路由。产物是方案，不改业务代码。

完成标准：区分现有/拟新增，未来LLM范围明确，账本能指出下一步。状态：已完成。

### P1：独立提示词库，可实际使用

任务：建立独立配置/存储/版本与API；增加工具入口及用途→模型→编辑布局；完成视频/图片/剧本分类、模型分支新增/重命名/排序/移除恢复、条目移动与另存，以及文本新建、编辑、搜索、筛选、收藏、复制、移除恢复。剧本普通文本管理本期直接可用。保护未保存编辑与冲突；核对新增数据目录的打包排除及可用备份方式，不能误报现有资产备份已覆盖新库。

完成标准：通过用途与模型找到、创建和修改条目，重开可读取；分类移动不改正文版本；分支移除不丢条目且可恢复；通用与待归类含义明确且可管理；未保存离开按公共规则处理。必要检查：临时库API保存/冲突/版本/分类归属与恢复，一次含分类操作的库页面核心操作。不用真实生成或大型库压测。

### P2：五模式共同工具栏与普通文字复用

依赖P1。任务：按4.3节核实来源关系并接入公共目录元数据；五模式全部接入公共工具栏、保存上下文自动识别用途/提示词家族、当前家族与通用定位、选择预览、替换/插入、展开编辑、收藏；接入原保存成功后的自动收录、幂等补记和作用范围。支持换人补充说明/完整正文的显式区别；完善必要的可选使用来源标记保存，不只写前端。

完成标准：在五模式保存上下文正确归为H3/Krea2，同家族文件版本不拆分，保存项目自动收录且无需手动分类，相同内容重复保存不重复；手工模板不被覆盖；能收藏当前文字并使用库中固定版本；取消不改项目；应用只改当前草稿；保存重开文字与来源准确；运行/锁定保护保留。必要检查：公共操作一次；五模式各自的真实保存→自动收录→家族/字段绑定各覆盖一个代表路径，补一例重复保存幂等与一例库失败单独重试。图片不操作真实标注生成。公共修复不能只接一个模式就将本阶段关闭。

### P3：结构字段组合和输入引用检查

依赖P2。任务：按现有模式能力收藏正文/声画等字段组合；应用前列出字段和格式转换；调用原有效输入检查；必要时提示完整正文与structured的切换后果。保留未选字段、素材和配方。

完成标准：结构组合不被当作普通正文重复包裹；取消保留全部字段；缺引用有明确反馈；不自动改编号或工作流。必要检查：一个支持组合的视频场景、一个不支持字段的图片/接续场景、一个引用缺失场景；复核直接受影响的原编译绑定，离线检查即可，不执行生成。

### P4：生成记录回看与收藏来源

依赖P2，结构记录依赖P3。任务：统一读取具体输出的实际文字；结果与来源区提供查看/复制/收藏/用于草稿；保存来源身份，复用精确项目定位。复合成片按真实片段/内部任务展示，不能拼成一条伪造的“最终prompt”。

完成标准：修改项目当前正文后，旧结果显示的仍是当次文字；未记录的内容明确空缺；收藏不选用、不生成；库条目可回到实际来源或显示移除/缺失。必要检查：按三种实际记录结构（原视频、图片、接续）用临时记录核对；复合成片采用一例，复用已有定位检查，不再重跑全部来源体系。

### P5：未来接入约定与同批收口

依赖P1～P4。任务：复核库是否独立于具体模型/模式；写新增调用方接入说明，更新公共组件归属和准入表；整理用户使用说明及阶段证据。确认数据目录不进入源码分享，不自动制作新工具包或发布。

完成标准：P1～P4均有具体实现和必要检查记录；未来剧本/LLM约定清楚但没有提前实现；维护入口能准确路由下一次新增工作。只核对接口与文档，不为抽象扩展点搭建LLM模拟平台或复杂测试工程。

## 10. 检查与同批交付纪律

用户已明确：不为了确保没有任何问题无限扩大测试。每阶段只运行直接相关的必要检查，通过后继续交付；真实生成、大文件断网、超大库、长期多窗口和整体操作体验由用户反馈，不作为本计划未完成事项。

必要检查优先覆盖真实保存/字段绑定、取消保护、版本稳定及本次改动涉及的异常。公共组件至少横向核对受影响调用方；已有有效检查可以复用，不重复造同义测试。文档变更只做文档/链接/维护索引检查。

每次实际开发必须同步：本文账本、维护基线、项目地图、相关功能/公共归属文档、必要AGENTS正文。新增前端按现行要求运行 `node tools/check_experience_contract.mjs`；检查器不变时不额外测试检查器本身。
