# 剧本与电影创作：交互流程纠偏方案

2026-09-09，现行纠偏方案，已合并用户后续关于无段落层级、资产卡片、跨页目录及继承关系的纠正，并在用户“开始执行”后落实。本轮实现与验收范围见[交付说明](../frontend/creation-experience-implementation.md)。未调用真实模型或操作生产项目内容。五页剧本、两页电影保持；本文件纠正当前实现的交互流程，不重启全站架构工程。

## 一、重新界定完成标准

用户要的是在一个连续工作空间里，与LLM共同完成故事、资产剧本、分镜和生成Prompt，随后用电影模式生成和剪辑。

纠偏前的实现以内部数据层为中心：逐层展示标题、正文、ID与参数表单，然后在表单下方追加AI工具。虽然有真实API、持久化、候选和生成通道，但主要操作顺序没有体现用户的创作过程。前序“E0—E6本期完成”只可保留为历史工程交付记录，不能继续代表这两个模式的功能与体验整体完成。

纠偏不以“所有按钮存在、能保存、CSS相同”为完成依据。必须能够沿故事起点，经过沟通、输出、确认、资产需求分析与绑定、完整资产剧本、分镜、分镜下的片段、Prompt、片段生成，直到剪辑导出完成一次可理解的流程。使用临时项目与fake模型验证即可，不扩大为真实生成或压力测试。

## 二、实施前核对的具体差异

| 真实入口 | 当前行为 | 需要纠正的结果 |
|---|---|---|
| modes/authoring/workspace.js 的 blocks/render | 第二、三页先绘制整组标题/正文表单，AI区域追加在后面 | 第二页以沟通和LLM输出为主，第三页以剧本与资产落实为主 |
| 同一文件的左侧目录 | 根据已有blocks直接列段落，父入口与段落缺少专门的层级布局；点段落主要滚动到整页某处 | 完整剧本不切业务段落；分镜和片段在后续阶段才形成；目录点击跳转到对象所属页面 |
| features/authoring-assist/index.js | 用ctx.aiInstruction保存一个临时输入，输入本身不进入原保存脏状态；各页复用这个值 | 按项目、阶段、对象隔离沟通草稿，原保存机制能持久化与恢复 |
| 同一文件的 jobs/candidates 过滤 | 按目标ID筛选但未充分按阶段/任务分开，无目标任务可在不同页显示 | 剧本、资产分析、分镜、Prompt各自显示对应结果，不串页、不串对象 |
| h3ui/creation/writing.py | 请求以system+本次上下文组成，已有任务和候选不等于连续对话；没有明确的“基于这次输出继续修改”交互关系 | 记录用户消息、所基于结果、输出和正式版本之间的关系，支持有范围的多轮沟通 |
| service.confirm与前端确认/下一步 | 后端记录内容哈希确认；目录直接取内容，下一步与确认状态的业务衔接不明显 | 明确保存、确认、按创作进度形成分镜/片段目录、阶段就绪之间的关系 |
| 电影模式 | 已有固定来源、选用、同步、横轴及剪辑操作 | 保留机制，围绕“当前片段→当前选用→成片顺序”重审用户路径；未见具体证据的项只标待核对，不一律认定错误 |

上一轮实际查看了用户指定剧本的第二页。该项目已有完整剧本候选，但主区先出现空段落标题和正文，沟通框与候选被推到后面，印证上述流程偏差。只浏览，未提交生成、应用或确认。

## 三、先把四种内容分清

1. **沟通内容**：用户的要求、追问、修改意见及LLM解释。保存对话不等于修改剧本。
2. **本次输出**：LLM这次交出的完整剧本、局部修改、资产需求、分镜、片段或Prompt。可以反复生成和比较；未确认不得替换正式内容。
3. **已确认内容**：用户明确采用的版本。后续阶段引用它；用户手改或上游变化后可变为待重新确认。
4. **目录结构**：已确认内容的组织方式。仅有完整剧本/完整资产剧本、分镜、分镜下的片段；没有“段落”业务对象。自然文本换行不构成导航或资产作用域，旧block不能直接当作新目录。

用户可手动修改LLM输出，也可以直接导入/粘贴已有剧本。手工编辑是输出区的编辑动作，不把默认创作页面变成要求从空段落表单起步。

## 四、五页剧本分别如何工作

### 第1页：故事起点

收集故事/想法、参考图片、期望时长和创作偏好。主区输入，右侧参考资产；不混入第二页LLM剧本候选。主操作为“进入剧本创作”，把已保存起点作为第二页初始上下文，不自动发模型请求。

没有LLM也可保存项目。未填写完不丢失输入；未完成状态明确，但不强迫用户凑齐虚假信息。

### 第2页：剧本创作

左侧为跨页面的项目目录。中间上方与LLM沟通，下方阅读、修改本次输出，右侧提供创作参考。初次沿用第一页的故事/图片/时长；后续可基于当前未确认输出继续修改。确认完整剧本只形成正式剧本，不切分镜、更不创建“段落”。

第一、二页可以添加资产作为创作参考。用户已明确的关系（如“这张图作为女主角”）记录并带到第三页；只上传、未明确用途的素材不能自动绑定某个角色。局部文字修改可定位原文，但不建立段落对象。

### 第3页：资产绑定与完整资产剧本

保留左侧跨页项目目录，取消右侧属性栏。其余主区域采用上方资产需求/绑定、下方剧本的专属布局。第三页不按点击的分镜/片段筛选内容；点左侧这些对象直接跳到第四/第五页。

流程明确为：已确认完整剧本→用户发起资产需求分析→LLM返回结构化需求→网站生成待绑定卡片→用户补充/核对绑定→用户发起生成完整资产剧本→阅读修改输出并确认。需求分析和资产版写作是两次不同的明确任务，不在页面打开或确认时自动发起。

LLM需告诉用户每项需求的名称、类别、特征、用途与剧本中的使用位置。网站结合已提供素材和已确认关系显示已绑定/待补/待确认，不能让LLM猜测整个资产库里有没有。第三页之前已明确的绑定直接带入；推测匹配只作为建议供用户确认。

上方按角色、场景、服装、道具、声音、风格等分类生成卡片。例如缺三个角色就直接出现“张三”“王五”“李四”三个框，用户往对应框选择或拖入素材，而非先添加一堆无归属素材再手动分类。各卡片复用资产选择器、本地上传、预览、更换、解除绑定能力；解除不删除原资产。用户可改需求、合并重复角色、补遗漏、删除误判或标为仅用文字/暂缓。已绑定数量和待补筛选可见，完成类别可收起，避免资产区无限增高挤走下方剧本。

同一角色跨情节复用身份；不同服装/状态是该角色的使用设定。服装须说明穿着者，场景/道具须说明用途和使用位置，风格须说明作用范围，声音须区分参考用途。点击使用位置，在下方剧本高亮原文；此时不建立分镜或片段，也不创建段落ID。

资产绑定是网站保存的事实。用户整理好后，LLM依据已确认完整剧本和固定资产关系生成完整资产剧本；不得编造资产ID、未见图片细节或把全部资产说明机械拼成正文。下方切换原剧本与本次输出，允许提出修改并确认；上方资产卡片持续可见。

重新分析需求保留仍有效的绑定，只核对新增、变化和移除项。更换素材不自动改写剧本、发起模型请求或清空后续。补图沿用保存/不保存后直接进入图片模式的流程，返回核对具体已入库版本。

### 第4页：分镜设计

从已确认完整资产剧本发起分镜。左侧目录第一层保留完整剧本/完整资产剧本入口，分镜确认后纵向出现；分镜下切好片段后再显示片段子项。没有段落层级。

本页需要详细与LLM沟通，因此复用第二页的主区版式：上方沟通、下方输出，右侧显示当前分镜的资产及来源。全剧分镜草案先核对后确认；点某个分镜后，沟通和输出围绕该分镜。原剧本依据可以展开查看，不用标题/正文空表单挤走沟通区域。

分镜明确画面、动作、声音、时长意图，并选择适用模型/工作流。再在分镜下整理生成片段：从当前分镜拆解，不重新从整篇剧本无归属切分。用户核对切分结果后形成片段目录，切分不自动生成视频。默认沿用原H3路线，合法帧预算用于提出可审核的片段方案，不静默拆任务。

### 第5页：片段创作与Prompt

沿用跨页目录。点片段才进入此页并定位该片段；仍复用第二页的上方沟通、下方输出版式，右侧显示本片段实际采用的资产及来源。原完整资产剧本/父分镜的依据可展开对照，不与当前输出或用户要求混为同一字段。

用户与LLM细化当前片段并编写正式视频Prompt。依据父分镜、当前片段意图、明确生效的资产、所选模型/工作流和真实输入槽生成文字与编号。高级结构化字段按需展开；确认按片段进行。

已确认、待核对、未编写状态在目录可见。部分片段未完成也能保存或导入电影，但未就绪对象不能误提交生成。电影沿用这里的稳定分镜/片段关系。

### 跨页面目录的统一行为

目录按实际创作进度形成，在返回早期页面时也保留。完整剧本→第二页；完整资产剧本→第三页；分镜→第四页并定位；片段→第五页并定位。点击不是当前页筛选，不把第三页改成片段资产编辑页。跳转沿用公共保存/放弃/取消及位置恢复，当前页和当前对象选中状态明确。

### 全剧、分镜、片段的资产来源

全剧基础为第三页确认的资产关系。分镜默认沿用全剧，片段默认沿用所属分镜的最终有效设定（包括该分镜继承的全剧资产）。同一资产身份不因层级变化复制为多个角色。

| 编辑对象 | 可选来源 | 默认 |
|---|---|---|
| 分镜 | 沿用全剧资产 / 本分镜独立设定 | 沿用全剧 |
| 片段 | 沿用所属分镜 / 直接沿用全剧资产 / 本片段独立设定 | 沿用所属分镜 |

“独立设定”是局部引用/用途的修改，不是复制文件或另建资产库。来源选择可作为该对象的基础策略；右侧每项仍须显示实际来源，单项替换只覆盖该项，不隐式切换其他资产。

例如全剧张三穿常服、分镜2设定穿雨衣：其片段2-1沿用分镜时为雨衣，来源显示“分镜2·独立设定”；片段2-2明确选择全剧时为常服，不能仍取最近父层；片段2-3局部换外套时显示“本片段独立设定”。张三的身份仍是同一对象，服装局部改动不能无意替换人物外貌。

右侧资产区须同时展示：基础来源、有效素材缩略图与名称、用途/对象关系、逐项来源、局部修改标记。“查看来源”能去第三页或对应分镜；“恢复沿用”清楚说明恢复哪层。若片段沿用分镜而分镜沿用全剧，可显示“沿用分镜2 → 全剧资产”，避免来源标签只写含糊的“继承”。原分镜中的素材与本片段是否使用也分开：不出场/不使用可显式标记，不能把未使用误报为缺资产，更不能把全部素材送入模型。

全剧改动只影响选择该来源且未被覆盖的项；分镜独立设定不受无关全剧变化影响；片段直接沿用全剧时绕过分镜替换；片段独立设定不反写父级。来源更新先提示核对，已确认正文/Prompt、已提交生成和剪辑继续使用各自固定快照，不在后台悄悄换图。

每次LLM请求和视频准备由网站解析有效关系与固定资产版本，再转换为该工作流实际输入槽；LLM不自行猜继承优先级。素材缺失、来源移除、同名不同对象或重复槽位要明确提示，不静默选择其他图。旧版本依旧可追溯。

## 五、两页电影如何衔接

### 第1页：片段生成

左侧纵向分镜—生成片段目录，使用剧本顺序；清楚区分待准备、可生成、生成中、有候选、已选用。

主区以当前片段结果和候选为主；原剧本/Prompt用于核对，有准确返回修改入口。右侧放当前输入资产、生成关系和来源。公共制作参数保留。电影不设置另一个剧本LLM沟通区。

导入不等于立即生成。缺Prompt、素材或模型适配时，在对应片段说明缺什么、去哪里补；其他就绪片段仍可工作。生成后查看、选用、加入资产库各自独立。

源剧本变化只提醒有更新并允许选择同步，保留旧候选及旧片段关联，不自动重生视频。续接必须记录本次采用哪个上游结果，不能随着上游改选偷偷换依据。

### 第2页：剪辑拼接

首次进入以生成页顺序和已选用结果形成默认横向时间轴；如需要初始化，作为进入时可理解的动作，不把数据库初始化术语交给用户。已建立的剪辑不因切换页面而重新排列。

时间轴操作对象为实际片段。轴上看顺序、长度、选择与播放位置；轴下是当前片段裁切、纳入/排除、生成关系与剧本来源。上方保留有效预览区域，主要完成动作位于右下角“拼接导出”。

用户不满意画面，可从片段关系返回该次生成及候选；不满意内容，可返回准确剧本/分镜/Prompt对象。修改后返回原剪辑位置，由用户决定是否替换新结果。不能为重新生成把整个剪辑丢掉。

## 六、真正需要统一的公共机制

**阶段工作区**统一主/辅布局、目录选中、输入与输出槽、操作区、状态及恢复。第二/四/五页的上下沟通/输出及右侧资产、第三页的上方资产/下方剧本且无右侧栏、电影横轴分别使用任务适配，不再无条件复制同一套三栏表单。

**LLM创作会话**按项目、阶段、对象隔离。记录未发出的输入、用户每次要求、依据的输出/正式版本、实际附带资产、任务和输出。切换对象不串话，刷新不丢输入。复用原项目存储/任务/候选，不另建独立聊天系统。旧job与candidate可投影为历史记录，缺失的对话不能伪造。

**请求上下文**明确本次修改基于哪一稿；连续修改可引用未确认输出。后台选取当前目标及必要上层上下文，不简单把所有层全塞进请求。过长时明确提示或按确定规则裁剪；额外摘要调用不能偷偷发生。

**模型输出合同**分离解释/追问与可采用内容；资产需求、分镜、片段输出带可校验结构，完整剧本自然换行不产生业务层级。Prompt/TXT执行模板、任务注册、API与页面同批改，不能只挪动textarea就宣称完成多轮沟通。供应商配置保留可编辑模型ID，不借纠偏自动换模型。

**保存与确认**：保存保留工作进度及沟通草稿；发送产生一次明确请求；确认采用核对后的版本；下一步改变阶段。按钮根据当前任务命名，避免“应用到当前正文”“确认当前内容”“下一步”三个模糊动作让用户猜。允许草稿探索/部分导入，不用全项目硬锁代替就绪提示。

**修改影响**：上游改动保留后续已做内容，按原版本/身份链标记“来源有更新，待核对”；展示影响对象和去哪里修改。候选、正式版本和剪辑状态不可相互代替。

## 七、实施顺序与有限验收

1. 先落实第二页完整链路和共享会话机制：起点→沟通→输出→继续修改→确认完整剧本，不生成段落目录。同步存储、请求上下文、模板和取消/保存；以它作为其他写作任务的接入基准。
2. 接通第三页LLM需求分析→自动生成命名卡片→绑定→完整资产剧本输出→确认；落实主区上下布局、补图返回与既有绑定保留。
3. 接通第四、五页分镜→分镜下切片段→模型适配Prompt；复用沟通/输出版式，验证跨页目录、三层来源选择与逐项局部覆盖、稳定身份和局部确认。
4. 逐项复核电影导入、生成/选用、默认剪辑顺序、来源返回及显式更新；只改实际差异，保留已正确的生成和媒体机制。
5. 最后统一空态、忙碌/失败、缺资料、长正文、窄屏和返回位置；更新准入任务卡和维护状态，后续新模式按同一会话/作用域/确认机制接入。
