# 项目指令、现行文档与状态的持续维护

这是每次开发交付的职责，不是定时后台服务。维护者负责内容判断，`context_guard` 负责发现已配置文件与上次复核快照的差异。工具不会自动编写规范，也不能证明文字正确。

## 单一现行来源

| 内容 | 唯一详细入口 |
|---|---|
| 长期规则、授权边界、开始顺序与任务路由 | [AGENTS.md](../../AGENTS.md) |
| 代码位置与专业文档地图 | [PROJECT_GUIDE.md](../../PROJECT_GUIDE.md) |
| 当前事实、真实差异、任务状态、验收边界与交接 | [maintenance-baseline.md](../maintenance-baseline.md) 的当前区 |
| 字段、保存及执行绑定 | [parameter-map.md](../frontend/parameter-map.md) |
| 公共交互规则与工作流演进 | [参数交互契约](../frontend/parameter-and-interaction-contract.md)、[工作流适配](workflow-evolution-contract.md) |
| 快照范围和真实版本来源 | [context-check.json](context-check.json) |
| 最近一次内容复核回执 | [context-review.json](context-review.json)（由工具生成） |

AGENTS 的受管索引仅为上述状态的短摘要，不是第二本手写台账。当前没有独立正式版本文件，配置读取 `static/index.html` 的 app.js/style.css 资源版本并要求一致，标为“静态入口版本”。不把 V4、API v5、资产库 V2 或历史前端版本混作网站的新版本。以后引入正式版本来源时同步修改配置及说明。

代码说明实际实现，已认可的产品规则约束目标；冲突时分别记录现状与目标，不能把未经授权的代码偏离写成新的产品原则。旧材料保留为历史证据，不继续指挥当前开发。

## 每次开发的闭环

1. 从真实维护目录开始，读取有效目录指令、地图、当前状态和本任务相关说明，查看未提交差异。运行一次只读 `check`；有漂移时先核对变化组，不覆写用户工作，不启动网站探查。
2. 在任务开始说明目标、复用点、真正变化、保护范围和最小检查。小修复只需一段；同用途工作流才需要说明业务适配缺口，正常模型文件更新无需开发任务单。
3. 修改实现时同步相关专业文档和维护基线。长任务在可恢复节点记录已做、正在做、未检查/未生成与下一步；短任务不按行记录流水账。
4. 交付前审核 AGENTS 正文/路由、PROJECT_GUIDE 和检查范围。路径、命令、公共规则、功能名称或责任变化必须修改；没有变化时保留稳定条文。解决的待办移出当前区或标历史，不能只改日期、复制旧验收数或追加多个“当前版本”。
5. 完成内容复核后才执行 `record --reviewed`，摘要写实际行为、相关文档判断和验收边界。源码变化但对应说明仍准确时给具体 `--no-doc-change-reason`，不能为了通过检查随意触碰文档或统一写“内部修改”。
6. 最后运行一次 `check`，按本次影响完成另需的相关检查。实现、相关文档、当前状态、AGENTS 必要正文与索引同批交付；未授权提交时留在同一工作树，不能为同步文档自动提交或推送。

代码已经完成、文档下次再补，不构成完整交付。只读咨询没有变更时不为形式写快照。正常创作中的调值/换兼容模型不触发开发交付，更不能阻断用户生成。

## 哪些变化要维护正文

| 变化 | 必须复核/更新 |
|---|---|
| 同功能新增工作流 | 模块说明、参数映射、工作流能力与必要依赖、当前状态；AGENTS 路由若不变可保留，刷新索引 |
| 新字段或参数行为 | 字段映射、公共交互契约及使用说明、当前差异；不要往 AGENTS 复制字段表 |
| 公共 UI、功能入口或会话行为 | 前端规范、相关地图与模块约定；AGENTS 对应规则/路由同批修改 |
| 目录、检查命令或版本来源改变 | 地图、入口、检查配置、AGENTS 中所有受影响的路径/命令 |
| 内部修复且现行说明仍准确 | 状态与实际检查结果；明确说明为何不用改对应专业正文，仍审查 AGENTS |
| 用户修订产品边界、子目录指令冲突 | 按当前授权校准有效规则；不能删除 override 或改全局设置绕过冲突 |

## 开始、记录与检查命令

以下命令从仓库根目录执行，仅使用 Python 标准库。本机已存在 `.venv\Scripts\python.exe`，也可用已有的 Python 3.10+；不得为运行这个工具安装升级生成环境。

```powershell
.\.venv\Scripts\python.exe tools/context_guard.py check --root .
# 完成语义核对和本轮相关检查后，才记录实际摘要
.\.venv\Scripts\python.exe tools/context_guard.py record --root . --reviewed --note "本次实际修改、相关文档更新与未验证范围"
.\.venv\Scripts\python.exe tools/context_guard.py check --root .
```

仅内部修复且关联专业说明仍准确时，给具体原因，例如：

```powershell
python tools/context_guard.py record --root . --reviewed --note "修复重复订阅；已更新维护状态" --no-doc-change-reason "仅修正内部清理，原生命周期说明和参数行为仍准确"
```

`record` 只写配置指定回执与 AGENTS 标记间的索引；AGENTS 正文仍由执行者合并。状态正文不复制回执时间、散列或当前检查次数，以免循环改动。状态记录本轮的内容复核和检查种类，最终快照一致性以最新回执和现场 `check` 输出为准。

返回码：`0` 为记录成功或快照一致；`1` 为需要复核（包括首次没有回执、文件漂移、索引不同）；`2` 为配置/输入错误。首次缺回执是预期状态，先读文档，不能直接盲目 record。

工具隔离自检命令：`python tools/test_context_guard.py`。使用临时资料，不导入网站模块，不使用真实项目/资产或引擎。

## 覆盖范围与语义局限

配置指向指定源码、文档、入口、维护工具和相关指令文件，检查文件集合与内容指纹、必需路径、版本证据以及受管索引。增加新目录或移动入口时同时调整配置；不能靠缩减范围掩盖过时说明。既有 `tools/check_repository.py` 只检查 Git 暂存内容/分发风险，两者职责不同，不能互相替代。

工具不运行 Git、网络、网站或 ComfyUI，不导入 `h3ui`，不扫描模型、作品、资产库或真实运行配置。它不验证全部 Markdown 链接，不自动发现配置外的新模块，也不判定全局或某层指令是否被客户端加载。新会话仍须检查实际目录链及相关子目录指令。

指纹相同只证明所选文件与复核时一致；文档被改过、理由非空或 `--reviewed` 都不证明内容正确，更不证明 UI、参数绑定、生成、性能和用户验收通过。执行者须先读相关差异，再记录。

默认有单文件、总量和文件数上限；超限先排查是否选入本机节点大缓存或产物，再对真实源码范围作必要调整。不要纳入权重与媒体。记录写入中断后下次 `check` 可发现不一致；重读差异后重新记录，不删除资料“恢复通过”。

## 新会话与中断交接

阶段 A 曾核对仓库及父目录相关指令；以后出现子指令仍要重新核对。不要假定旧会话会自动更新磁盘规则：新会话从真实目录开始，跨版本、切分支或规范实质变化后显式重读。当前状态写“实施中”时应先检查工作树，不能把聊天中的完成描述当成可覆盖文件的依据。

主动暂停前尽量写短交接，不承诺突然断电或被强制结束时一定来得及保存。续接沿用真实差异与当前授权，不重新执行历史计划。本次阶段 B 已获授权并接入图片参数修复，阶段 A 的未提交维护内容继续保留；具体已做、检查进度和待验收状态只读维护基线。以后的附件或历史待办仍不能自行扩张授权。

## 执行机制与分享

本轮未安装 Git 钩子、未修改 CI 或全局 Codex 设置。现在由每次开发任务在开始和交付前显式执行，不宣称放入文件就已自动强制。未来经相应授权可在既有交付脚本/CI 接入只读 `check`，不让无人值守的流程自动 `record` 掩盖漂移。

回执不应写入密钥、私人素材或用户项目数据。公开分享仍走 [原 Git 分享说明](../github-sharing.md) 和 [检查与交付](checks-and-release.md)，保留第三方来源与现有历史。代码回退不恢复用户数据，不整目录覆盖旧备份。
