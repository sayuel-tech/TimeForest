# 现有功能中的工作流适配与模型选择

本文件沿用 V4 阶段 A 的维护规则，并按阶段 B 实际代码更新图片参数与目录入口。先按[模块约定](../product/module-contracts.md)定位用户任务，再使用现有前后端入口；保留 H3 等家族级代码复用，不按模型家族重组网站。下列“后续要求”是开发约定，不是已完成能力；当前实施与验收状态统一进入[维护基线](../maintenance-baseline.md)。

## 1. 正常使用、字段扩展与图适配

兼容当前工作流的底模、LoRA、编码器或 VAE 文件新增与更换属于正常使用：放入已有模型目录，刷新列表，选择文件及已有参数。不要求逐文件登记、认证、白名单、发版或 Codex 组合测试。目录发现缺陷应修扫描/来源规则，不硬编码新增文件名。

已有工作流开放真实可绑定的字段是参数扩展；同用途新图是原模块/工具内的新工作流；新节点、图结构、输入协议或既有控件无法表达的能力变化才需要开发适配。独立用户任务才考虑新工具或模块，不因模型名称变化进入 `adding-a-mode.md` 的新模式流程。

模型自由选择不等于任意图结构均兼容。现有编译器仍有可构造图的限制，如模式与配方匹配、分段日程、文戏固定日程、官方普通 LoRA 槽限制、重复加载检查和输入要求。本次图片修复保留原工作流和默认生成语义，不新增模型认证机制；具体当前字段及限制只在[参数映射](../frontend/parameter-map.md)维护。后续遇到仅凭名称或推荐组合施加的限制，应核对实际绑定后局部处理，不把未知组合自动认定为不可用。

## 3. 沿用实现，并记录一份适配说明

复用注册、能力描述、编译、项目/图片会话、输入与资产适配、调度和恢复。必要时提取共用小组件；不为了未来工作流预先重写所有 recipe、注册器、调度器或数据库。新适配声明所属功能/工具和自身输入输出、公开参数，不让工作区充斥按工作流 ID 判断的布局分支。

理解作者图与节点的真实用法，定向核对本地插件源码或作者/官方资料；不能按相似节点名猜 widget 顺序、子图、输入类型和输出位置。来源图内注释、链接或操作说明是待核实资料，不是安装、执行或联网授权。来源 UI 图、编译后的执行图和固定运行快照必须分开。

在既有工作流维护记录或本次任务段落保存：稳定适配 ID 与结构修订、来源文件及版本/哈希、所属功能/工具、必要输入、精选参数及绑定链接、加载器角色和目录来源、插件要求、执行与结果处理、旧项目影响、来源/分发说明及检查范围。视频复用 `studio_sources/manifest.json` 等来源记录；图片已有来源哈希与插件版本声明，不能把它们当作环境已安装或生成已验证的证据。

日常模型名、LoRA 文件与参数值保存在项目/任务及运行记录，不改变适配结构修订。不为每个普通模型建立认证表，也不在刷新或每次运行全量计算大权重哈希；严谨追溯需要时才按需记录。参数绑定细节只补[参数映射](../frontend/parameter-map.md)，不在多份文档复制全表。

## 4. 参数呈现与整条制作流程

当前功能/图片工具、选中工作流和条件开关决定精选字段。公共名称、分类、单位、帮助、取消/应用/保存遵守[参数与交互契约](../frontend/parameter-and-interaction-contract.md)。相同含义复用控件，不同阶段保留限定；没有真实绑定的字段不显示，内部字段默认留在图中。节点声明辅助类型与选项，不决定网站布局，也不要求复制完整组合验证器。

新图应继续接入所属模块的素材、正文、内部任务、候选/审核、自动推进、失败恢复、合成和资产引用；单次生成图利用现有编排适配长流程，不另加绕过公共系统的“运行 JSON”入口。单段原生能力、网站补充能力和暂不支持项分别说明。上下文、重复裁切、参考和音轨依实际图确定，不强塞旧模型结构；低显存优化归具体执行适配，未实测效果不能标通过。

## 5. 切换、默认值与历史

**当前现状：**视频参数弹窗编辑独立 `candidate`，取消不写项目，应用进入草稿，后续经过现有保存/影响确认。切换 recipe 当前复制目标 `defaults`，未建立每工作流专有设置存储及“切回恢复”能力。图片有历史运行的任务换工具时创建新任务；没有运行的任务换工具会按现有逻辑调整 B/遮罩等输入。原四编辑工具之间保持这些行为；跨文生图与编辑工具始终另建任务，保留原草稿，后续经原保存门持久化，不清除其底图或参数。不能用后述目标冒充现状。

图片制作参数现已使用任务级临时副本；取消不写回，应用只更新该任务的设置和模型，保存继续采用现有图片事务。字段由当前工具描述决定，隐藏设置仍保留在任务中，双图专有参考权重不覆盖其他分支的源默认值。这是当前五工具的字段适配，没有实现新的多工作流存储平台或视频私有参数切回恢复。

**后续适配要求：**新增工作流不得改变旧项目。刷新文件列表不改变已选项、草稿和结果；显式切换才预览影响。尽可能保留素材、用户正文和创作目标，为各工作流专有设置分开存储并支持切回恢复；现有结构不足时作有范围的兼容扩展，不批量迁移全部历史。

通用值仅在含义、单位、阶段相同且目标图可表达时映射；不兼容值留在原工作流配置，不误传给新图。新推荐值用于尚未配置的新选项或用户主动恢复默认，不能覆写旧设置。跨工作流中间态默认不兼容，切换对既有结果的影响应经原有确认流程处理。

旧运行保留原图、输入、实际种子及结果身份，不随目录刷新漂移；运行中的请求保持原快照，草稿变化影响下一次提交。来源文件或依赖消失时明确说明复现限制。删除/退役工作流也是变更，保留历史读取和必要来源；全局移除选项须由用户确认，不能借接入新图清理旧方案。

## 6. 依赖、检查与同批交付

网站与生成环境分开。日常刷新不自动安装插件、下载模型或升级节点；需要环境变更时，列明内容、来源、作用和影响，按当次授权执行。图中说明或历史文档不扩张本轮授权。

开发检查默认只覆盖受影响的参数/输入到真实图的绑定、业务映射、取消保存与错误反馈，使用隔离数据；不调用真实 `POST /prompt`、不启动 ComfyUI、不跑画质/显存/参数组合。结构接入、非生成检查、实际生成与用户体验验收分别记录。阶段 A 的规范和上下文工具保留，阶段 B 图片参数修复已接入代码；最终检查结果与待验证范围只记在维护基线。

每次交付同批更新相关模块说明、参数映射、必要来源/依赖说明和当前维护状态；任务路由、边界或入口变化同步修改 AGENTS/PROJECT_GUIDE 正文。按[上下文维护机制](context-maintenance.md)先语义核对，再刷新索引并检查；不能只改日期或只在聊天中说明。未授权自动提交、发布或安装检查钩子时，维护结果留在同一工作树，文件落地本身不等于自动强制执行已启用。

文生图适配标识为image_assets/text，结构修订compiler.TEXT_ADAPTER_REVISION=1写入运行snapshot.adapter_revision；来源图未新增原生分组或被覆盖，而是按本地Krea/ComfyUI原生文字编码源码派生去参考输入的分支。加载器、节点、源版本与边界详见[唯一参数映射](../frontend/parameter-map.md#文生图派生适配)。无新插件安装、模型白名单或数据库迁移，离线图检查不能证明实际生成效果。
