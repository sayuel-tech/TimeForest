# 运行来源与未入库下游 · 本地6.3.30

接续6.3.29，本批补齐前三视频未来运行的上游身份，以及资产到项目生成结果的反向查看。现行三阶段进度：第一阶段已实施，第二阶段核心路径已验证；第三阶段已覆盖本机已记录来源的上下游，外部素材包的显式跨库身份映射仍待完成。缺少元数据的历史关系无法自动恢复。

## 实际变化

1. 原三视频在创建运行时，通过`generation/source_lineage.py`保存`source_lineage.version=1`，同时写入原manifest和候选记录。输入来自实际resolve/inventory，保留引用用途、Picture/Audio标签、项目素材身份及库内固定asset/version/media/hash；换人源视频也读取其固定引用。不存资料PROMPT或从文件名推导身份。
2. 上游候选保存project/segment/run。分镜外层与内部任务分别记录；第一内部任务继承外层已冻结父身份，后续内部任务明确保存所属外层候选及internal_segment/internal_run。旧外层缺身份不从当前选用补齐。新增内容只是元数据，不替换previous上下文、不改编译图、随机数、提示词、采样或恢复规则。
3. 来源解析可从三视频候选继续追到前一候选和库内素材。候选入库沿原ResultImports携带记录；只读解析按指定运行目录读取原manifest，不查找“最近的文件”。旧编排记录可继续解析，跳转时仍由source-target核对当前页面是否可定位，不能暗中恢复旧编排。
4. 资产详情和选择器新增“查看项目中的生成结果（含未入库）”，与“已入库的下游结果”分别展开，共用descendants-view的分页/失败留存/重试/关闭后迟到响应保护。查询三视频候选与当前成片、图片输出、视频接续生成/导出结果；包括已移除项目、任务废弃和保留的历史编排。
5. 项目结果链接带确切候选/输出/成片标识及原资产返回位置。查看不选用、不入库、不保存，不触发生成。是否入库仍读原资产回执；此列表包含项目结果，不把它包装成“只有未入库”或猜测入库状态。

## 分页与边界

新只读接口：`GET /api/v5/library/assets/<id>/generation-descendants?version=...&media=...`。后续请求原样传回cursor/before。每批最多处理25个记录位置/空项目，查询起始时间限制新增或后来完成的结果；项目候选按稳定ID分页，状态切换或片段排序不靠数组下标推进。图片按输出rowid推进。读取的是实时保留记录，不锁定生产项目，不构成全库事务快照。

失败/未完成运行、接续导入/准备记录不冒充生成结果。旧元数据缺失、循环、来源不存在等计入不完整提示。未知不等于“没有下游”。来源图仍沿6.3.29的16层/64项上限。大型库按需继续读取，不在打开页面时自动扫描到底。

`origins`声明generation_descendants_version=1。新前端遇到旧后台明确提示待保存/结束任务后重启，不能把没有入口当作没有结果。本批没有重启用户网站。

外部包身份映射尚未实现；不同安装的同名/同编号不自动关联。本批没有改包格式、创建数据库表或迁移历史。前三视频新增元数据只对以后创建的运行生效，旧记录缺失身份仍显示未知；真实生成和长期大规模使用等待用户体验。
