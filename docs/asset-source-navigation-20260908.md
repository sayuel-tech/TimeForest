## 用户可见变化

- 在资产来源面板点击项目，有记录身份时打开对应位置：前三视频进入所属片段的制作与审核，并展开右栏中该次历史候选；图片进入对应编辑任务及确切图片候选；视频接续进入所属续写段及历史候选，成片来源进入导出步骤。
- 定位只改变查看位置。图片不更改项目保存的current_task，五模式不自动选用、保存、应用参数、恢复或生成。提示可关闭；有固定资产身份时提供返回该版本资产的入口。
- 记录已移除、所属任务已废弃或身份不匹配时明确提示，并提供对应回收站入口；不声称已定位，不以最新结果冒充该次来源。工作区原有内容仍可继续使用。
- 修正上一批项目回收站链接：使用真实资产路由`#/assets?view=trash&recycle=projects`，不再进入普通资产列表。
- 前三视频新登记成片保存export_created作为导出身份。只有与项目当前导出匹配才定位当前成片；旧资产缺确切标识、或项目已经重新导出时，提示限制并保留固定资产查看。

## 公共实现与适配

AssetOrigins只从固定媒体provenance提取task/segment/run/output/export_created；origin_*查询与原有asset导入参数隔离。旧项目只有项目身份时仍打开项目。来源链上每个节点的返回链接锁定该节点的资产版本和媒体。

`static/studio/core/source-target.js`统一身份校验及只读查看位置；`ui/source-navigation.js`统一提示、返回资产和回收入口，复用公共notice/row/quiet样式。三个工作区控制器只适配自己的tab、shot、task、clip、extension与候选查看状态。前三视频历史视频在原右栏展开，不替换项目已选用结果。原bootstrap离开保护和业务动作保持原入口。

后端`asset_library/results.py`仅为今后登记的成片补导出身份，不改历史operations或既有资产provenance。`origins.py`生成来源链接；参数仍来自原固定记录，绝不从当前项目补齐。
