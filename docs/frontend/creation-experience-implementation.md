## 页面与操作

| 页面 | 本轮运行行为 |
|---|---|
| 1 故事起点 | 保存故事、偏好、时长和创作参考。进入下一页不自动发起请求。 |
| 2 剧本创作 | 主区上方提出要求、选择修改依据，下方阅读及编辑输出。可以基于尚未确认的输出继续沟通；确认后在同一输出区继续修改。右侧为创作参考。 |
| 3 资产落实 | 保留左侧跨页目录，取消右栏。主区上方为分类命名资产卡片，下方为资产需求分析／完整资产剧本写作。两个任务分别显式发起，输出不会串到其他页。 |
| 4 分镜设计 | 全剧分镜草案确认后形成目录；点击分镜后只沟通该分镜。分镜下切片段时，后端校验全部片段属于此分镜并合并保存，保留其他分镜内容。可设本分镜默认H3工作流。 |
| 5 片段 Prompt | 点击片段定位此页；可细化片段剧本或编写正式 Prompt，两者沟通独立保存。右侧显示生效资产及来源；原有工作流、时长、连续关系与实际正文/编号核对保留。 |

目录是跨页面导航。完整剧本到第二页，完整资产剧本到第三页，分镜到第四页，片段到第五页。目录状态区分草稿、已确认、待核对、待编写 Prompt。旧链接若将片段传给第四页，会定位到其父分镜；直接进入片段页会展开所属分镜。不存在“段落”导航或资产作用域。旧 `blocks` 的内容和身份仍读写，全文编辑保留其身份，不批量迁移旧项目。

输出确认写入现有内容层及确认记录。确认后的最新输出显示当前已保存内容，可以直接编辑并“保存并确认修改”；历史候选保留原始回答。手工粘贴剧本仍可在已保存内容区进行，无须先调用LLM。下一步只导航，未完成内容可以保存或导入电影。

## 命名卡片与真实资产关系

需求来自 `asset_analysis` 候选，用户确认后网站分配身份并形成卡片；LLM不直接建立绑定。分类包括角色、场景、服装、道具、声音、风格和其他。卡片显示名字、描述、落实状态、固定参考和来源；支持资产库选择、本地文件上传/拖放、使用前两页已提供的参考、改名、补遗漏、解除、暂缓、仅用文字和不在本处使用。重复需求可显式合并，保留目标已存在的绑定；原件与历史不删。

服装、角色声音用 `subject_ref` 关联角色需求，选择素材前核对该角色；上传素材不会被默默当作另一个人物。可选 `source_text` 记录剧本原文短摘录，点“查看使用位置”在原剧本中定位。旧需求没有摘录时不伪造位置。重新分析保留有效需求身份及已有绑定，新增内容才分配新身份；模板要求模型不得猜测整个资产库。

分镜的基础来源为全剧或独立设定；片段为所属分镜、直接全剧或独立设定。基础来源与逐项覆盖分开：切换基础来源后，显式局部覆盖仍可在卡片中看到并恢复“沿用”。局部文字说明保留原有效图片，不把角色图片意外替换成纯文字。每张卡显示实际来源入口；“本处不使用”只停用当前范围。

后端 `h3ui/creation/bindings.py` 是写作和电影共同的权威解析入口。前端 `binding-cards.js` 对未保存草稿使用同样解析顺序供即时展示，保存与提交最终由后端校验。新绑定携带准确 `reference_id` 和固定资产版本；相同媒体用于不同需求时保留独立的用途引用。旧绑定继续按固定资产/版本读取。缺少有效引用时明确报错，不悄悄遗漏输入。

电影沿用原冻结来源包与显式同步。更改剧本绑定、正文或工作流不会覆盖已经保存的电影来源、候选和剪辑；电影准备阶段仍阻止未确认 Prompt 或待落实资产误生成。剪辑页“回剧本修改分镜”本轮纠正为父分镜ID，保留回到电影原片段的位置参数。

## API、存储和模板

- 原项目文档新增 `writing_drafts`，按 `layer:target_ids` 保存沟通要求、是否附图、选定依据与未确认输出编辑；没有新建数据库或LLM会话系统。
- `POST /api/v5/authoring/projects/{pid}/conversation` 使用原revision、请求幂等回执及该对象的 `base_hash`。冲突保留当前输入；不同页面或对象不能借另一个对象的候选继续写。
- 快照增加 `creation_experience_version=2`、`writing_draft_hashes`、`writing_target_hashes`。旧服务不支持新版保存时给出明确提示，不能假装已经保存。
- 最近四轮本对象的请求/输出及用户明确选定的输出进入LLM上下文；选定输出含用户已保存的未确认编辑。其他对象沟通不混入。上下文、正式输出及历史候选分开。
- 分镜／片段的局部确认独立记录。更改某片段不取消其他片段确认；下游内容更改不会把上游已确认完整剧本误标为待核对。
- `运行模板/*.txt`、需求/绑定schema、会话请求schema、OpenAPI与实际路由清单同批更新。H3输入编号来自实际input contract；工作流与默认采样语义保留。本地LLM仍只预留，不自动换模、修复格式或调用模型。

运行资源位于 `h3ui/creation/resources`。本轮未重新发布或替换旧桌面ZIP；再次分发应从现行资源制作新包，不能把旧V3.0 ZIP称作本轮纠偏版。

## 复用边界与验收

第二／四／五页共用 `authoring-assist` 的沟通、输出编辑与确认生命周期；第三页按资产绑定任务采用专属上下布局。公共页头、步骤、底栏、工作区、属性面板、选择器、上传、参数弹窗、错误、计时、视图状态保护继续使用现行组件。没有另造视觉皮肤或把其他五模式改成剧本页面。

[隔离证据](../evidence/creation-experience-20260909/README.md)包括真实临时API/资产库/项目持久化与fake模型末端、宽窄浏览器链路、既有电影操作、补图保存/不保存、轮询展开与输入保护。图片仅用32×32合成色块；电影末端使用假媒体。没有用户项目或密钥进入证据。

本轮证明保存、作用域、继承、确认、导航和输入绑定的实现，不能证明真实LLM会稳定生成满意剧本、准确识图或生成连续视频。这些实际效果、长篇创作中的主观阅读感受及日常使用仍待用户体验反馈；不为消除所有假设风险扩大压力测试。
