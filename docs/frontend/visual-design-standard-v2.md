# 时间森林设计规范 V2：以任务和可阅读性分配界面



2026-09-09。本版替代V1的设计判断依据。延续纸色、水彩、森林绿及公共交互生命周期；尺寸标尺只负责基础一致性，不能决定内容优先级。



**状态：R1—R4本期改造已实现并完成必要隔离检查。** 查找/全文、各模式长正文、资产预览与资料、媒体审核、配置和管理页按任务调整；实际差异与保留范围见[交付](readability-implementation.md)，证据见[截图与检查](../evidence/readability-v2-20260909/README.md)。用户后续审美与实际使用反馈继续接入，不以检查数量声称不存在问题。



## 1. 先确定任务，再选布局

表单宽度补充（2026-09-09用户反馈）：创作表单的多行输入框应铺满所属字段区，与同列时长等输入左右对齐，不套用只读正文的920px上限。属性栏展开/收起后仍保持对齐。下文行宽目标用于只读阅读，不得据此缩短表单输入框并留下空白。


每个页面/步骤必须先回答：



1. 用户来这里要完成什么？例如“找到适合当前片段的提示词并应用”，不能只写“展示提示词库”。

2. 为作出决定，必须看清什么？区分完整正文、候选差异、媒体细节、参数值等主要信息。

3. 高频操作及先后关系是什么？从真实查找、阅读、修改、选择、保存与返回出发，不能按已有按钮反推任务。

4. 什么信息只在需要时查看？来源、历史、分类、参考资产、日志按任务决定主次，不能因为有组件就永久占一栏。



判断顺序：**任务能完成 → 内容能读懂或比较 → 操作能找到且后果可预测 → 视觉协调。** 美观服务于前三项，不能为了整齐减少正文面积、缩字或隐藏决策必需的信息。



具体页面见[页面任务与改造清单](page-purpose-design.md)。布局可随任务状态变化，共同动作的语义、状态和位置规律保持一致。



## 2. 统一任务框架，不统一所有页面的列数



| 框架 | 主区域 | 辅助信息 | 适用页面 |

|---|---|---|---|

| 查找/挑选 | 候选列表或素材网格；能辨认差异 | 分类、筛选；详情按需打开 | 提示词/资产选择、档案 |

| 阅读/写作 | 完整正文或当前编辑内容 | 大纲、参考、来源按需查看 | 剧本、Prompt、长资料 |

| 预览/比较 | 媒体有效画面、原片与结果 | 候选条、状态和必要参数 | 图片挑选、视频审核、媒体详情 |

| 编排 | 当前片段及其顺序、轨道 | 所选片段操作和来源关系 | 视频接续排序、电影剪辑 |

| 配置 | 字段名称、完整值、必要解释 | 分组、高级选项 | 制作参数、服务配置 |

| 处理/整理 | 对象、状态和处理后果 | 分类、批量选择、日志 | 任务、回收站、分类管理 |



复用的是这些框架及交互机制，不是固定三栏。一个页面在查找和阅读全文时也可以换主区域。



## 3. 空间首先满足主任务



- 侧栏有当前用途才显示。未选对象时不能保留空详情栏挤压候选；短详情不能永久占据宽屏的一半。

- 列表查找时，摘要必须足够区分候选；阅读时完整正文要有连续、舒适的阅读面，不放进窄属性卡里。

- 只有需要同步对照时保留并排区域，例如原片/结果。来源、历史和帮助通常无需与全文长期并排。

- 长正文初始以约30—45个中文字符一行、行高约1.7—1.9作设计起点。这是本项目待验证的目标，不是普适达标值。中英混排、列表、模型名和代码分别处理。

- 宽度不足时收起辅助区或切换主视图，不缩字来维持列数。大屏不无限拉长正文行，多余空间可用于有价值的比较、候选或侧边留白。

- 留白不能与主内容被挤压同时存在。若某一区域需要频繁滚动，而旁边只有少量说明，先重新分配空间。

- 正文和列表使用扣除必要头部/操作后的可用高度。不能未经任务验证就限制为36vh/40vh，再在外面留下无法利用的空白。

- 列表摘要可以截断，但必须有清楚的全文入口。当前编辑正文、关键操作后果及必要错误说明不能靠省略号隐藏。

- 收起辅助栏只改变视图，不清空素材、不卸载未保存草稿；仍用既有视图状态与异步保护。



## 4. 字号按阅读角色分配



| 文字角色 | 新设计目标 | 使用规则 |

|---|---|---|

| 长正文/编辑内容 | 初始16—18px；行高1.7—1.9 | 剧本、Prompt、片段描述；正文颜色，段落清楚 |

| 候选标题/摘要 | 标题16—18px、摘要15—16px | 用于辨认差异，不能全部变成淡小字 |

| 字段、界面名称、常用按钮 | 14—16px | 同角色同尺度，名称、值和操作易读 |

| 辅助元信息 | 13—14px | 时间、编号、版本；不能承载核心内容 |

| 页面/弹窗/区域标题 | 保留共同层级，按任务校准 | 用于定位，不挤占正文面积 |



上述数值用于设计判断，不能只凭数值宣称体验达标。2026-09-10源码核对：design-tokens.css已有 text-reading:17px、text-summary:16px、leading-reading:1.8 和 reading-width:920px。后续核对实际组件是否消费相应角色，不直接放大所有pre或所有按钮。



Prompt是创作内容，不是日志。即使用pre保留换行，也要独立正文样式，不能继承通用代码块13px字体。日志、JSON、原始错误可以用受限等宽区；面向用户的错误摘要和下一步操作须正常可读。



字体和布局一起验证。只放大字号导致行更短，或者只加宽却仍用13px正文，都不算解决。



## 5. 提示词选择器的目标设计



### 当前问题



修订前的styles/prompt-library.css固定分类、列表、详情三栏；列表max-height:40dvh、详情正文max-height:36dvh。.prompt-text未声明字号，继承base.css中pre的13px；列表摘要14px且最多两行。这是本次已修复的问题记录，不是现行呈现：现在查找与全文分别占主区域，使用独立阅读角色。


这些问题在尺寸断言全部通过时仍会存在。上一轮几条相近短句不能代表用户实际阅读、辨认与比较提示词。



### 查找与阅读两个视图，保留一个选择会话



**查找视图：** 顶部搜索及当前用途/模型范围，左侧精简分类，剩余主体给候选列表。条目呈现标题、有辨识度的摘要、模型和必要状态；取消常驻全文详情栏。



**阅读视图：** 打开某条后，完整Prompt占主区域。标题、用途/模型、版本作为简短页头，来源/历史默认折叠。提供返回列表、上一条/下一条及原“选择此提示词”动作，不为读下一条强迫用户反复关弹窗。



返回列表恢复筛选、页码、滚动和当前条目。窄屏沿相同路径完成，不先滚过全部列表才能读全文。取消不修改创作正文；选择仍只返回候选，后续字段核对、应用、保存保持原语义。旧版本查看和选择保留。



提示词管理页复用查找/阅读组件，另配编辑、分类、移除和备份。选择器聚焦本次选择；管理能力仍在库中，不删除原功能或改分类数据。



这套布局只作为文字查找与阅读的基准，不套用到视频审核、图片画布和时间轴。



## 6. 控件、操作和状态



- 主动作、普通动作、紧凑工具与图标使用各自公共规格，不能随模式任意放大或缩小。通过层级和位置区分主次。

- 查看不应用，应用不等于持久保存，取消不丢弃外层草稿；“返回列表”和“退出创作”后果不同，必须准确命名。

- 常用动作靠近被操作内容；整页保存/推进沿公共底栏。历史、来源、原始日志下沉，不能抢占主任务首屏。

- 主操作必须能看出对象和必要后果。选用候选与加入资产库是不同决定，不能合并；停止必须指出具体任务。

- 加载、空结果、未选中、长内容、运行、失败及部分完成分别考虑。空态不预占整栏，失败保留已有内容，进度不挤走正文。

- 焦点、键盘、关闭、草稿、轮询和视图恢复沿用公共机制。不能为布局切换重新实现一套保存与状态系统。



## 7. 响应式保住任务



以容器中主内容是否仍可读判断能否保留多栏，而不只按固定断点。先减装饰/多余间距，再收起低频辅助区，再切换单主视图；不能先缩正文。



常用桌面宽度、窄容器及一次125%浏览器放大后都应能完成主要任务，不要求所有信息同时出现。同一阅读任务通常只有一个正文滚动容器；目录可以独立滚动，但不能弹窗、列表、卡片、正文层层截短。



底部动作要可达且不覆盖末段；切换候选、开合来源和返回列表后保留位置。媒体保持比例，禁止为视觉整齐裁切真实生成画面。



## 8. 美观如何评审



保留原站基调和克制边框。主内容成为视觉焦点，辅助信息适度退后；标题颜色一致、按钮同高只能证明部分样式一致。



先看截图能否辨认主区域与下一步，再读真实内容，检查淡色、小字、窄栏、截断和复杂滚动是否阻碍判断。每块长期占据空间的区域都须说明它此刻帮助用户完成什么。



## 9. 实施与新页面准入



1. 先实施提示词查找/阅读与公共阅读样式，验证真实长度文字及返回位置。

2. 核对剧本与Prompt编辑/阅读，保留五页剧本、两页电影及原业务。

3. 核对媒体预览/比较、资产网格/详情与轨道编排，使用各自可辨认性标准。

4. 核对参数、任务、首页、档案和管理页。合格的现有区域保留，不能为改造数量重做。

5. 同批记账：待改造、已实现、已检查、用户反馈待处理分开。代码或测试记录不得提前记为体验完成。



普通页面、新步骤与新模式开发前都要填写[页面任务卡](page-purpose-design.md)：任务、主信息、主操作、辅助信息、布局状态、公共组件、必要例外、验收例子。只有designScale复用声明不够。



check_ui_design只检查变量与加载归属；check_experience_contract只检查登记结构。保留其防回归作用，不将其当作可阅读性评分，也不增加空泛布尔字段制造“通过”。这些检查仍由维护任务执行，不是自动安装的CI或后台服务。



## 10. 必要验证与停止条件



用可读、彼此有差异的临时内容完成实际任务：从候选找到适合镜头者，读到末段限制，查看旧版本，返回列表，再进入原应用流程。不要用六条几乎相同的短句证明阅读体验。



文字例子包含短摘要、约600字Prompt、约1500字分段剧本、中英混排、长文件名与素材标记；这是有限界面样例，不是压力测试。媒体例子包含横/竖比例、可辨认的候选和长标题。任务例子包含等待、处理中、失败及可操作说明。



完成标准：主内容能读完或看清，需要比较的信息可同时看或方便切换，动作可达且对象明确，返回恢复位置。无溢出、按钮同高、页面数量只作辅助证据。



每类受影响任务完成代表流程并核对截图后停止常规检查；不运行真实生成、大型库、长时多窗口或无止境验证，日常审美和使用效果接受用户反馈。
