2026-09-08，按用户“继续”落实第四批，保留前三批界面及所有模式的业务流程。本批代码在原目录修改，未提交或发布。

## 用户可见变化与共同入口

| 场景 | 实际修复 | 共同入口与适配 |
|---|---|---|
| 状态响应晚于输入、保存或切页 | 按项目对象、编辑代次和revision判断旧读；编辑/参数弹窗/播放时不替换草稿树。图片不再独立实现轮询；接续编辑期间仅合入运行事实，避免断开输入闭包 | core/async-state.js、progress-channel.js；ProjectSession、ImageSession、接续工作区 |
| 断线恢复 | 五模式在稳定位置显示最后已知状态及原始错误；下一次成功读取清除连接错误，不宣称任务失败或停止 | ui/async-feedback.js；原运行卡仍显示业务阶段 |
| 上传 | 文件传输百分比与服务器读取/处理分开；传输100%不当成处理完成。错误保留原文，不自动再次上传 | core/upload-client.js的uploadForm；原uploadAsset保留包装，前三视频素材、图片输入、接续原视频/参考输入通过各自API适配。资产库既有分块续传保持 |
| 提交响应丢失 | 保留“提交结果待确认”，重新提交前要求读取实际状态；图片保留既有提交key，接续保留原revision/后端保护 | async-state的uncertainMutation/requireKnownStatus与原命令门；只重读，不自动生成 |
| 弹窗关闭、另开或切页 | 资产选择器的初始目录、搜索、详情请求绑定各自生命周期；过时查询不覆盖新弹窗。入库弹窗初次查询同样受保护。成片存储信息只写原节点 | modalTicket、scopedModal、AbortSignal及原业务调用方 |
| 重复操作与全局队列 | 保留保存合并，补独立草稿/新建项目防重；忙碌更新不重新启用“已选用”。队列旧轮询不能倒退操作反馈，停止请求只显示请求状态，销毁后迟到结果无效 | 原singleFlight/ProjectCommands、task-center及core/task-state.js |
| 入库后重新进入项目 | 前三视频读取真实完成入库记录，候选和成片可恢复“已入库/查看资产”；文件版本变化不沿用旧回执，资产已移除时仍保留真实入库事实 | ResultImports.outputs→LibraryStore.import_receipts→result-import，使用既有operations和assets，无迁移 |

入库状态通过`GET /api/v5/library/projects/<pid>/outputs`返回`result_receipts_version=1`与条目的asset/asset_removed。只认准确媒体登记token及完成导入键，不按名字匹配，不写回或回填旧项目。不存在资产或未完成操作不会显示已入库。图片与接续既有持久字段保持。旧后台缺契约时给出明确重启提示，不能以空记录冒充已查证。
