# 新增功能的共同体验准入

适用于新增模式、页面、弹窗、操作、字段、工作流适配和公共样式修改。功能可以不同，共同操作的含义、位置、反馈和草稿保护必须延续。标准来自[体验一致性方案](../product/experience-consistency-plan.md)，具体实现归属查[公共组件](shared-ui.md)，不能从另一个模式复制一份作为新模板。

## 开工前：先确定继承什么

在本次开发记录中写清用户任务、作用对象、已有公共入口、业务适配与验收场景。小改动直接写入维护基线或相关功能文档；复杂功能使用下方模板，不强制每个字段新建文档。

- 已有完整组件：复用其外壳、样式、事件与关闭生命周期，模式只传数据、能力、插槽和业务命令。
- 已有组件缺能力：优先扩展共同接口，同批检查所有受影响调用方。
- 尚无完整组件：在本次授权范围内建立最小公共入口再接入，不能为了赶进度新增模式私有的保存/参数/计时/错误框架。
- 真正的业务差异：如图片画布、视频分镜、接续轨道，保留独立实现与数据模型。是否有某个动作可以不同，同名动作不能有隐藏的不同后果。

不适用必须有用户任务或底层能力依据。“这个模式单独做”“工期紧”“原来就不同”都不是理由。公共规则变更须更新唯一规范和全部受影响调用方，不能在模式说明中单方面改写。

## 实施与交付门槛

1. 公共呈现改共同层，禁止复制公共组件或用模式 CSS 覆盖共同容器、字号、留白来另造样式。专属画布等样式仍限定模式作用域。
2. 公共动作遵循统一语义。参数写临时副本，取消无副作用，保存失败保留输入且阻止后续生成；选用、入库、继续制作明确区分。无法兑现的动作不得提供假按钮或静默降级。
3. 新模式完整走共同脚本；普通新增功能走相关场景。公共组件改动列出全部调用方，逐一填写实际检查/不受影响的依据，至少横向审视五模式。不能把只验一个模式写成全局通过。
4. UI、交互和真实数据绑定分别验收。视觉仅截图、数据仅假 API、测试仅 import，都不能替代其他层的检查。沿用隔离资料，不运行 ComfyUI 验收这些改动。
5. 有缺口就标待完成，保留原保护和恢复路径；不能通过隐藏按钮、更新日期、登记文件、修改豁免清单把缺口变成完成。
6. 同一交付更新功能文档、公共归属（如有变化）、当前维护状态及必要 AGENTS 路由，运行相关检查后再 context record/check。

## 可执行结构检查

```powershell
node tools/check_experience_contract.mjs
node --test tests/experience_contract.test.mjs
```

`experience-contract.json` 记录公共入口与模式接入。工具只加载模式注册表，不调用工作区 load、API、模型或生成服务。开启两个既有模式开关后核对当前注册表，检查新增模式是否登记、公共入口/适配/证据文件是否存在、九类场景是否有记录。它不扫描未注册页面、不分析 CSS/调用链、不执行证据文件，也不能判断证据内容是否真实。

五个现有模式在 `baseline` 明确保留上轮审查缺口，结构检查通过不代表这些缺口完成。只允许既有五个 ID 使用历史基线；逐个完成整套验收后移入 `modes`，不得提前清空缺口。新增模式必须使用 `modes`，不能新增历史豁免。

`modes.<id>` 的登记格式：

```json
{
  "review": "docs/实际功能接入记录.md",
  "shared": {
    "settings": {"kind": "reuse", "adapter": "static/studio/实际适配.js", "reason": "提供当前对象的临时草稿与保存命令"}
  },
  "scenarios": {
    "parameters": {"status": "checked", "reason": "填写实际结果", "evidence": ["docs/实际检查记录.md"]}
  }
}
```

这是局部格式示例，不能直接当成完整登记。`shared` 必须逐项填写 chrome（页头与步骤）、settings、models、workbench、actions、references、timing、errors、candidates、results（候选状态与结果操作栏）、playback（视频播放）、async（读请求归属与草稿保护）、transfers（文件传输与处理阶段）、taskStates（任务事实文案）、modal；适用时使用 reuse 并给适配入口，不适用使用 not-applicable 并说明业务依据。`scenarios` 必须逐项填写下表九类；checked 附实际证据文件，不适用也必须给依据。证据可以引用真实执行记录与测试代码，但路径存在不等于执行通过。

本地维护任务在每次前端开发交付前运行结构检查；检查器本身修改时运行其测试。当前未安装 Git 钩子或 CI，不能宣称无人值守强制执行。结构失败或实际场景失败不能宣布该功能体验验收完成；既有基线的通过提示始终列出待完善模式。

## 同批开发记录模板

复制到当前功能文档，填实际结果；不要预填“通过”。

- 用户任务、对象和作用域：
- 新增/改动入口、调用方和复用组件：
- 独立业务部分及依据：
- 公共能力缺口如何处理：

| 场景键 | 应核对的操作 | 预期/实际、证据或不适用依据 |
|---|---|---|
| navigation | 参数/返回/下一步位置；加号就近操作；离开不暗中丢稿或停止任务 | 待填写 |
| import | 本地/资产库同级选择；目标明确；取消、失败和固定引用保护 | 待填写 |
| parameters | 实际字段；取消/X/Esc；默认值；刷新保留选择；应用与保存作用域 | 待填写 |
| save | 修改、保存失败、重试、保存重开；成功反馈与实际持久化一致 | 待填写 |
| generation | 保存失败阻止提交；防重；排队/运行/停止未确认；计时 | 待填写 |
| results | 再生成保留历史；查看/选用/入库独立；播放及业务后续 | 待填写 |
| recovery | 说明移除对象和回收位置；运行/选用保护；恢复不生成 | 待填写 |
| async | 双击、关闭重开、切页、迟到响应、输入期间轮询及请求失败 | 待填写 |
| visual | 宽窄屏、长内容、空/忙/失败态；对齐/密度/字号/留白横向对照 | 待填写 |

- 自动/隔离检查：命令、实际结果及局限。
- 受影响模式逐项结果：参考视频换人、参考图长视频、文生视频、图片资产创作、视频接续；新增模式另加。未检查不能写通过。
- 仍待用户日常体验/真实生成验证：
- 同批文档、当前状态、AGENTS变更与撤回范围：

不附真实私人作品、账号路径或运行记录作为公开证据。沿用现有发布边界，此规则不授权自动提交或发布。

结果入口须区分查看、选用和入库；纯图片业务可声明playback不适用。选用若还会继续制作或合成，按钮及确认必须说明后果；重新生成对当前选用和依赖结果的影响按原业务明确提示。第三批实际适配及原三视频入库回执局限见[第三批交付](experience-phase3.md)。

本地6.3.25新增异步准入：状态读取经watchProject及async-state，在接收时核对项目对象、编辑代次和revision；切页仅结束界面订阅。上传复用uploadForm，传输完成不宣称服务器处理完成；提交结果不明时先读实际状态，不自动重发。任务事实文案经task-state，停止请求不等于停止确认。新增模式必须说明async/transfers/taskStates适配；实际覆盖见[第四批交付](experience-phase4.md)。


## 资产专项准入（6.3.26）

新增assetSelection、assetOrigins、assetUsage、assetCollection四项shared声明；assetLifecycle为第十类场景。普通功能也适用：列明输入类型/用途/目标，复用选择器、固定版本来源、成功后的usage登记和确切输出入库。检查预览/取消无项目写入、保存成功登记、版本变化不暗换、入库持久回执、来源项目与派生、缺失原项目、回收后副本保留、资产资料不进入生成正文。模式不适用项须解释，不能只填文件路径就当实际通过。五模式历史baseline继续保留未验范围。当前接入和检查见[资产共同体验](../asset-experience-20260908.md)。

assetOrigins适配包含来源定位：复用core/source-target.js及ui/source-navigation.js，按当前模式定位确切候选/任务/导出。assetLifecycle增加检查来源跳转不写项目、轮询后仍查看原记录、返回固定版本、缺失/移除明确反馈；不能用打开项目首页冒充精确结果定位。实现及非生成证据见[6.3.27交付](../asset-source-navigation-20260908.md)。

资产添加准入补充：有未保存正文/参数时打开选择器、进入用途确认、检查后取消都要核对项目未保存及输入未丢失；新增本地添加也验证取消不上传。复用reference-metadata的用途定义/临时编辑和关闭生命周期，图片A/B按业务不适用用途。提交前取消与提交后收起含义分开；原三视频草稿库引用同时应用必须核对后端asset_import_draft_version。核心证据见[6.3.28](../asset-lifecycle-20260908.md)。

派生准入（6.3.29）：assetOrigins/assetLifecycle须声明冻结的父输入身份、边的业务含义、上游解析与已入库下游查找适配；参数只读，不从当前草稿、文件名或refs补链。新增能力复用lineage/descendants与公共来源视图。检查替换A/当前选用不误改历史、跨固定版本、移除/缺失/循环/限额、外部包编号隔离、读取/取消无写入、失败重试及宽窄展开。既有模式的历史限制不能成为新增实现缺失身份的豁免；证据与仍待完善项见[6.3.29](../asset-lineage-20260909.md)。

运行来源准入（6.3.30）：新结果类型同时检查固定输入身份捕获、上游解析、原项目精确定位、已入库及项目生成结果反查。原三视频经source_lineage捕获实际输入，不改变编译/种子/previous；内部任务必须保留外层身份。检查旧后台能力缺失、未入库输出、历史编排、运行完成/新增期间分页无错位及只读跳转。证据入口见[6.3.30](../asset-runtime-lineage-20260909.md)。

素材包准入（6.3.31）：新增来源类型必须声明固定资产边及包内传输行为，复用pack_lineage与公共来源视图。验证跨独立库的asset/version/media/hash映射、未包含源文件不自动收集、外部项目同编号不误跳转、原版本在编辑/重复导入/部分失败重试后保持、损坏身份和联合依赖循环在注册前拒绝。来源勾选与工作流资料独立，预览选项变化/关闭后迟到响应不得启用旧导出；缺pack_lineage_version=1须明确提示。检查源码结构不代替真实临时API宽窄操作，见[6.3.31](../asset-pack-lineage-20260909.md)。

## 检查范围收口（用户确认，2026-09-09）

用户已明确测试边界（2026-09-09）：以本次改动直接涉及的必要检查作为交付标准，通过后停止扩大或重复测试。真实生成、大文件断网续传、大型资产库、长时间多窗口使用及整体视觉/操作感由用户实际使用反馈，不主动搭建复杂压力或长时测试，也不将这些未测试场景列为阻碍计划完成的开发待办。出现具体反馈、已知失败或改动直接涉及相应风险时，再做针对性复现与检查。保留必要的数据保护、真实保存/参数绑定及受影响公共调用方检查；不把未测试说成已验证。

前述场景清单用于选择与变更相关的检查，不要求每次交付跑完整矩阵。公共功能仍遵循统一规范；用户反馈的具体不一致再纳入对应公共层与适配修复。

## 统一提示词接入要求（6.3.32）

新增模式须在experience-contract.json声明promptEditing、promptCollection、promptRecords及prompts场景；没有正文或生成的工具应说明不适用。正文位置/业务字段可不同，共享选择、收藏、复制、展开、取消/应用外壳；不改变工作流编译器。家族分类以实际主模型的上游证据为准，未知不阻止保存。

prompts场景至少记录：目标与真实模型分类；取消保留原文；显式字段应用；原保存成功后的自动收录及重复保存；库失败只补记固定快照；旧生成文字不被当前草稿替换。跨用途/不支持字段、素材编号和发声顺序要明确反馈。未来剧本/LLM沿相同内容/来源接口，不复用库存储作品、会话和凭据。具体入口与本期五模式证据见[提示词库](../prompt-library.md)。结构检查只查声明和文件，真实用户操作仍需对应必要检查。
