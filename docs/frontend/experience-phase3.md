# 共同体验第三批：候选、播放与结果操作（本地6.3.24）

2026-09-08，接续用户“继续”实施体验方案第三批。第一、二批既有修改保留，本批没有修改后端、工作流、默认生成语义或数据库。

## 已落地的共同体验

| 共同入口 | 责任与调用方 |
|---|---|
| `ui/result-view.js` | 候选状态、查看/决策/收藏操作分组与下载/入库回执。图片和接续共用候选按钮；三视频保留运行详情但共用状态及操作栏；五模式结果和视频成片共用操作分组。无业务请求或全局选用状态。 |
| `ui/media-player.js` | 四个视频模式共用播放/暂停、定位、读取失败与重新加载、独立打开；接续只提供播放器标识与业务来源。图片仍保留原图比较，不造视频控件。 |
| `ui/candidate-records.js` | 接续加入原地“已移除”与恢复，沿用原visibility API；三视频/图片原恢复保留。选用、运行中、未知提交等保护保留，恢复不生成、不选用。 |
| `styles/workbench.css` | 结果操作分组、候选状态与窄屏换行统一维护；删除图片候选私有样式及接续私有播放器布局。 |

“正在查看”“已选用”“已入库”分别来自查看状态、业务选用和成功入库回执。查看其他候选不改变选用；下载/入库作用于当前展示的具体结果。图片快捷入库保持当前步骤和选用。接续选用仍追加或替换同一轨道槽位，重复选用按钮禁用；继续续接明确沿已选结果，连播修正为操作中央播放器而非左侧缩略视频。

前三视频的选用继续调用原审核命令：末段或其余片段均已通过时显示“选用并合成”，自动推进显示“选用并继续制作”，普通审核显示“选用此结果”。重新生成确认明确取消本段选用并使依赖后续过期；旧候选文件保留。UI统一不改变原自动合成与依赖失效规则。

原视频结果入库弹窗保留原媒体选择、元数据、任务与去重链。增加初次打开防重、提交中防重、失败原文及成功后可打开资产；异步提交固定实际所选媒体，不因等待时修改选择而错记回执。**原三视频已入库标记仅当前工作区实例内保存，刷新或重进项目不猜测库侧状态。** 图片/接续读取原持久asset字段；本批不迁移数据或新增跨库查询契约。持久回执统一仍为明确缺口。
