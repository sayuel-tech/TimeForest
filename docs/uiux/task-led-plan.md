# 任务导向 UIUX：可中断实施计划

## 范围与基线

用户确认：气质统一、行为统一、组件统一，空间结构不完全统一。每模块先回答进入目的、第一眼对象、3～5个自然动作，再决定主次与布局。以本地baseline-v6.3.34为起点，保留后续工作树差异；不覆盖R1源码、不恢复左侧全站栏。当前唯一进度在[维护基线](../maintenance-baseline.md)，本文件定义批次与验收，不另维护完成状态。

每页目标写在pages目录原有页面卡，复用来源仍读common与catalog。首页原版森林主视觉和顶部导航是保留项；不预先安排重画所有页面。剧本/电影目前不可用声明继续保留，本计划的布局交付不能自动解除。

**Q0补充要求：以首页作为全站质感基准。** 11份页面卡的任务目标继续有效，统一继承[首页质感规范](visuals/README.md#首页质感基准用户确认2026-09-10)。不只做到颜色相同、控件尺寸相同；纸面、字重、边界、分组与反馈共同构成体验。所有Q1—Q7批次都应在主要业务动作可用之外检查这一层，不能为了密度把工作区改成小字、碎按钮和小缩略图堆叠的后台表单。

## 有限批次与顺序

每批先核对现状，未发现差异即可记录无需改动，不能为完成批次制造代码修改。父批次不同时开多个实现分支；每个子批独立保存和交接。

| 批次 | 有限用户流程 | 入口与依赖 | 完成条件 |
|---|---|---|---|
| Q0 | 设计目标、任务拆分与恢复机制 | 原11份页面卡、本计划、原维护基线 | 三问/空间/保留/检查场景落盘，索引检查通过；不是代码改造完成 |
| Q1 | 剧本资产需求→选择→绑定→查看剧本 | authoring卡；binding-cards/creation.css/原选择器；后端bindings只核对 | 8项混合需求可识别名字/类别/缺口；绑定或更换显示准确对象；取消无误写；原来源与更多配置可找到；正文可完整阅读 |
| Q2a | 完整剧本沟通→输出修改→确认 | authoring、authoring-assist、experience-content | 上方沟通下方输出；历史与当前编辑清楚；迟到刷新和保存失败保留内容 |
| Q2b | 分镜→片段→Prompt的对象切换 | shot-segment-tree、conversation、bindings | 目录跳到对应页和对象；资产明确沿用谁/覆盖谁；切对象不串草稿 |

## 共同行为与空间的判定

先列出本页主要对象、同时需要看见的内容和下一动作。写作给正文阅读/编辑空间；图片给画布或结果；审核给对照媒体；剪辑给片段顺序及所选操作；管理给查找和辨认。没有当前任务价值的属性区域按需展开。

公共机制沿用原保存门、revision、候选、固定资产、弹窗与轮询保护。选择不等于应用，应用不等于生成；查看不等于选用，入库不隐式选用；取消保留先前状态。模式可配置公共组件内容和业务回调，不能复制公共CSS或改变同名动作后果。

1366×768作为常用桌面窗口，另用一个窄屏代表。先验证主要对象、主要动作、长内容读取与局部滚动；不以零溢出或字号相同作为唯一指标。具体容量按内容任务判断，不把旧“6行”或4列网格硬套全站。

每批视觉复核将同一窗口的原版首页作为参照，并使用本页的实际长文、图片或候选状态；已有合适截图可复用作质感参照，但当前改动页面需核对真实呈现。先修空间分配/冗余层级，按需展开次要内容，再调整局部尺寸。禁止整页zoom、盲目缩小字号、复制首页大留白或给所有模式强制三栏。图像生成不属于默认检查，不为此调用模型。

## 每批操作与检查

1. 读维护基线、该批页面卡及至多必要公共专题，核对git status和当前实现；已有满足项保留。
2. 在维护基线当前工作项记下具体差异、准备改的文件及最小检查。对不明确的新业务先记录，不凭布局重排补造数据语义。
3. 修改最小完整流程；新增公共行为必须核对所有调用方，不只修当前截图。使用临时项目/库与fake末端，禁止真实LLM/视觉/ComfyUI/媒体生成调用。
4. 验证直接动作和取消/保存失败/迟到刷新这类相关异常；常规通过即可停止，不追加大库、长时多窗口或真实生成测试。
5. 同批更新页面卡、必要catalog和维护基线；UIUX检查与context record/check。标出实现完成、隔离检查通过、仍待体验三个不同结论。
6. 完成批次可按本次用户确认建立本地Git检查点；不自动push/tag/release，不移动baseline-v6.3.34。记录目的与范围；原维护origin不推送。

## 中断恢复

额度不能准确预知，不等到最后才写交接。完成可保存的小步骤就更新当前工作项；检查耗时前先记录入口。唯一当前位置写在维护基线，记录：批次和子步骤、修改文件、已完成内容、尚未完成内容、已跑检查及结果路径、未跑检查、已知失败、下一条具体操作、本地检查点。代码半成品明确标“进行中”，不冒充可用版本。

恢复先读上述当前位置、git status和对应diff；只核对漂移部分。发现测试进程未结束先判断归属，不重复启动；不要读取生产密钥/恢复旧生成队列。用户数据与工作树不清理。副本、旧脚本和截图只作证据，不从隔离副本继续开发。

新任务进入时先路由批次；用户的新反馈可以调整顺序，但不得抹掉原未完成记录。若某批只有方案完成而代码未动，必须直说。
