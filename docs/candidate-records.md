# 候选与生成记录整理

图片与三个视频模式共用“移除／恢复”语义，便于多次生成后筛掉无效结果。整理只改变列表可见性，不删除原文件，不释放磁盘空间，不改参数、种子、工作流或已有引用。

## 用户入口

- 图片“生成与挑选”：候选缩略图下方有“移除”。编号保留原顺序，移除候选2不会把候选3改成2。失败、取消但没有图片的记录在“未产生候选的记录”中整理。
- 三个视频模式：审核区右侧“运行”页签，展开对应记录后点击“移除”。当前接受结果保持原预览和下游流程。
- 移除前确认；移除后可在项目内折叠的“已移除”区或资产库→[回收站](recycle-bin.md)→“生成移除的”查看与恢复。恢复不自动选用，也不触发生成。全部候选移除时仍能恢复。
- 当前已选用的结果需要先换选另一候选。运行中、排队或待确认记录由原运行管理入口处理，不用候选移除解除占用。图片项目存在任一待确认提交时拒绝整理；视频未结束或可恢复的 interrupted 记录也不能移除。
- 图片沿用保存门，先保存当前任务草稿再整理；视频有未保存修改时沿用审核操作提示，先保存或放弃修改。版本冲突会拒绝操作，不覆盖他人修改。

已入库资产、已复制到后续图片任务的输入、视频固定引用以及历史成片保留。移除后的原候选不可直接选用、继续编辑或重新入库，先恢复再操作。资产库已存在的独立资产仍可正常使用。

所属项目已移除时，统一回收站仍列出生成记录并提示先恢复项目；恢复项目本身不复活另行移除的候选。列表分类与数量来自原标记，原局部恢复入口保留。

整个图片编辑任务可在任务目录“废弃当前任务”，同时退出工作区的是该任务及所有候选，并取消该任务的结果选用；已入库资产与引用保留。此操作区别于单条候选移除，恢复入口在“项目移除的”，恢复任务不会复活其中单独移除的候选或自动选用。详见[图片任务废弃](image-assets.md#编辑任务废弃与恢复)。

## 实现与数据边界

`h3ui/studio_records.py` 注册 `POST /api/v5/projects/<pid>/records/visibility`，请求含 `record`、布尔 `removed`、项目 `revision`；视频另传稳定的 `segment` ID。按真实项目类型分派，校验归属、终态、选用和版本，使用现有项目操作 lease 与存储锁。

图片在一个事务中给 run 和关联 output 写入 `removed_at`，视频写在 segment.attempts 的原记录上。恢复置空。均递增项目 revision；原记录数组、媒体、运行快照和库引用不删除，旧记录没有此字段默认可见，不迁移数据库。图片摘要封面/数量、候选选择与状态卡以及视频历史/候选入库列表过滤标记；原项目 API 保留未废弃任务的完整候选记录供恢复；编辑任务废弃后该任务与其运行/输出不在工作区snapshot中展示，原记录仍存储，需在项目类回收站先恢复任务。

共享组件 `static/studio/ui/candidate-records.js` 负责按钮、确认文字和已移除区。图片 controller 沿用 ImageSession，视频沿用 ProjectCommands；没有新建全局历史列表，全局队列继续只展示活动任务。

原视频“磁盘清理”仍是独立的主动文件清理操作，不属于本次候选整理。若用户另行清理了失败文件，恢复只能恢复记录可见性，不能重建被清理的文件。

## 检查与接续

`tests/test_candidate_records.py` 使用真实 Flask 路由、临时数据库、假引擎，验证三视频和图片移除/恢复、选用保护、归属/版本/占用拒绝、文件/快照/引用保留，以及旧入库令牌拒绝。真实图片 API JSON 交给实际 JS 呈现函数，再经真实草稿保存与重读，验证移除标记保留；不是浏览器点击测试。

`tests/studio_candidate_records.test.mjs` 验证可见候选、空态恢复、无输出记录、视频历史和操作保护。具体本次成绩、页面验收限制与服务加载状态只写在[维护基线](maintenance-baseline.md)。不得拿生产候选做试移除，不调用生成或引擎停止来验证。
