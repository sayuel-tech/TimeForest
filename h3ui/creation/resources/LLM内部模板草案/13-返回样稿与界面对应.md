# 返回样稿与界面对应

> V2.9：本文件为可读设计说明。未来运行读取 `运行模板/` 的对应纯TXT，任务/Schema/正文取值以 `配套清单/llm-task-registry.json` 为准；原“字段未定”说明不覆盖新合同。未进行模型实测。

**人工设计示例｜不是实际模型输出，也不是通过运行验证的契约**

以下四例完整展示建议的回应外层。它们用于讨论用户看到的内容，不要求正式实现照着示例字段建表。其他模板的 payload 说明同样需要在设计稳定后再形成一致的运行约定。

## 例一：局部改写

```json
{
  "contract_version": "tf-authoring/2.9",
  "task_type": "local_rewrite",
  "status": "ok",
  "payload": {
    "replacement_text": "她停在车门旁，没有伸手。风把裙角吹向车底，她低头看了一眼，又望向车窗。"
  },
  "notes": [
    "保留到达汽车旁这一事实，只调整动作节奏。"
  ],
  "issues": [],
  "questions": []
}
```

**正文编辑区只显示：**

> 她停在车门旁，没有伸手。风把裙角吹向车底，她低头看了一眼，又望向车窗。

说明单独折叠。用户复制正文，不复制“保留到达汽车旁……”；应用时也只替换原请求指明的那一段。

## 例二：一个分镜拆为两个生成片段

```json
{
  "contract_version": "tf-authoring/2.9",
  "task_type": "segment_plan",
  "status": "ok",
  "payload": {
    "segments": [
      {
        "ref": "new_001",
        "shot_ref": "shot_example",
        "text": "人物继续向前，步伐逐渐放缓，最后停下。",
        "planned_seconds": 8,
        "start_state": "人物正在行走。",
        "end_state": "人物站定，仍望向前方。",
        "dependency": {
          "kind": "independent"
        }
      },
      {
        "ref": "new_002",
        "shot_ref": "shot_example",
        "text": "人物低头看向脚边，保持站立。",
        "planned_seconds": 5,
        "start_state": "人物站定，仍望向前方。",
        "end_state": "人物低头，身体保持不动。",
        "dependency": {
          "kind": "upstream_tail",
          "upstream_ref": "new_001"
        }
      }
    ]
  },
  "notes": [
    "这里的时长与引用仅用于演示设计，未核验实际工作流。"
  ],
  "issues": [],
  "questions": []
}
```

网站将 segments 显示为两张自然语言片段卡，用户应用后才成为左轴里正式的两个子片段。临时 ref 在这次候选中表达关系，应用时由网站分配真实身份并同步映射，不让模型伪造稳定项目 ID。

依赖表示第二段预计承接第一段，不表示第一段已生成，不包含虚构 Take。它也不自动完成下一步 Prompt 创作。

## 例三：缺少必需执行约定

```json
{
  "contract_version": "tf-authoring/2.9",
  "task_type": "h3_prompt",
  "status": "needs_input",
  "payload": null,
  "notes": [],
  "issues": [
    {
      "kind": "missing_input_contract",
      "level": "blocking",
      "message": "尚未提供本次工作流的文案组装方式与实际参考标签约定。",
      "refs": []
    }
  ],
  "questions": [
    {
      "key": "input_contract",
      "question": "请先在网站确认本次工作流及其输入约定。"
    }
  ]
}
```

旧 Prompt 不变。网站在问题区显示缺口和返回设置的入口，不把“请先确认工作流”写入正式 Prompt。

这种网站已知的缺口最好在调用前发现；示例只是规定模型实际发现缺口后的呈现，不是建议每次花一次请求检查配置。

## 例四：Prompt 正文与说明分开

```json
{
  "contract_version": "tf-authoring/2.9",
  "task_type": "h3_prompt",
  "status": "ok",
  "payload": {
    "prompt_text": "暮色中，人物缓慢停下，低头看向脚边。风声渐弱，人物保持站立，没有对白。",
    "used_reference_keys": []
  },
  "notes": [
    "仅展示返回字段和界面分离；不是经过具体 H3 工作流确认的成品文案。"
  ],
  "issues": [],
  "questions": []
}
```

Prompt 编辑器、复制、保存和后续模型输入只取 prompt_text。notes 不进入视频 Prompt。具体 H3 需要的合法标题、参考标签和时序条件应由真实表达契约规定，不能因为本例简短就删掉正式工作流所需结构。

## 反例怎样处理

| 回答情况 | 建议的网站处理 |
|---|---|
| JSON 前后还有“好的，以下是” | 不直接塞进正文；显示结构不合格并保留原回答，可明确修复 |
| 对象可解析但正文只有几句梗概，却声称完整八分钟 | 结构成功不等于创作达标；展示真实内容，不将片长标签当完成证明 |
| 返回未提供的资产 ID | 引用校验不通过，不自动绑定或应用 |
| 对同一片段给出重复键或未知写入字段 | 严格结构检查，不用最后一个值静默覆盖 |
| status=ok 但含未解决的必需阻塞问题 | 不按正常候选应用，保留原因 |
| 流式半截 JSON 或推理文本 | 不作为可保存正文；进度与临时预览分开 |
| 用户在等待时修改了原文 | 保留候选供比较，不按旧输入覆盖新正文 |

这些是设计上的处理预期，不是已经运行的自动化测试结果。真正的创作质量、引用稳定性与模型兼容性，还要在后续明确授权的体验中判断。
