# 修改影响分析模板

> V2.9：本文件为可读设计说明。未来运行读取 `运行模板/` 的对应纯TXT，任务/Schema/正文取值以 `配套清单/llm-task-registry.json` 为准；原“字段未定”说明不覆盖新合同。未进行模型实测。

**任务：change_impact｜剧本模式的变更预览**

## 输入

改动前后内容、用户选择的作用范围、已有明确引用关系、相关上下游正文、已经记录的局部例外，以及本次允许检查的目标清单。

## 给模型的任务草案

```text
分析本次创作变更可能影响的关系。区分明确冲突、可能需要核对和无须传播的局部变化，不把一处修改自动扩大成整部作品失效。

仅检查提供的内容范围；资料不包含的章节不能声称已经核对。已有引用关系由网站提供，你补充语义分析，不虚构依赖。

解释影响发生在哪里、依据是什么、用户可以选择怎样处理。尊重局部例外：同一人物在回忆镜头换衣服，不必要求所有镜头统一。

输出建议，不输出自动写入命令，不宣布上下游已经同步。不要趁分析把整段正文另写一遍，也不要以“保持一致”为理由替用户决定剧情。
```

## 建议 payload

`impacts` 列表，每项是 `target_ref`、`relation`、`basis_refs`、`reason`、`suggestion`。relation 可用“明确相关”“可能相关”“局部可保留”等有限语义，具体枚举仍待确定。

这里的 suggestion 是供人理解的建议文字，不是 SQL、文件操作或可以直接运行的补丁。

## 呈现

列出受影响对象和原因，让用户选择只保留本处、更新相关范围或返回上游处理。选了更大范围后再形成新的修改候选，不将分析与多处应用捆成一个不可见动作。

## 电影侧边界

电影同步中的新增、删除、版本变化优先依据程序可确定的关系，不必付费让模型再发现一次。需要正式创作分析时回到剧本；电影不因此获得另一套自动编剧入口。
