# 生成片段模板

> V2.9：本文件为可读设计说明。未来运行读取 `运行模板/` 的对应纯TXT，任务/Schema/正文取值以 `配套清单/llm-task-registry.json` 为准；原“字段未定”说明不覆盖新合同。未进行模型实测。

**任务：segment_plan｜剧本模式第五页**

## 输入

当前确认分镜、已有片段与用户修改、完整对白、起止状态意图、前后关联，以及当前真实工作流的时长和输入能力摘要。

## 给模型的任务草案

```text
把当前分镜组织成适合制作的生成片段。以动作完成点、台词结束、情绪转折和镜头变化作为主要分界，结合网站提供的真实生成能力，不机械填满时长上限。

保留当前分镜要表现的事情，不为了容易切段改写剧情。动作或对白需要更多时间时明确指出，不把同一内容标成更短秒数就声称可以生成。

每段给出自然语言内容、计划时长、起始与结束状态，以及独立生成或依赖指定上游的意图。预期状态是计划，不是已经观察的视频事实。

片段之间需要连续关系时，只引用当前任务提供的上游或本回应内唯一临时 ref，不引用不存在的 Take，不形成自依赖或循环。

本任务只整理片段。不要同时输出正式 H3 Prompt，不宣称片段已确认，也不把拆分等同于实际提交生成任务。
```

## 建议 payload

`segments` 列表：`ref`、`shot_ref`、`text`、`planned_seconds`、`start_state`、`end_state`、`dependency`。

dependency 表达 `independent`、`upstream_tail` 或当前已适配的明确参考形式；取用细节由网站的真实输入契约决定，不由模型扩展任意类型。网站进一步检查引用与无环。

## 时长如何理解

计划时长是创作意图；工作流合法帧数与实际新增时长由适配器解释；后期采用长度在电影第二页决定。这三个长度不能合并成一个字段。

如某段难以在当前能力下完整表现，应提出问题或拆分候选，让用户确认。不要用后台自动拆句替代第五页的片段设计。

## 呈现

左轴在对应分镜下展开片段；中间展示所选片段的自然语言及起止状态。用户可以修改、拆分、合并和重排后确认，再进入同页的 Prompt 创作。
