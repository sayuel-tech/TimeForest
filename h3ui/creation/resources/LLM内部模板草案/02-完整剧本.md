# 完整剧本模板

> V2.9：本文件为可读设计说明。未来运行读取 `运行模板/` 的对应纯TXT，任务/Schema/正文取值以 `配套清单/llm-task-registry.json` 为准；原“字段未定”说明不覆盖新合同。未进行模型实测。

**任务：screenplay_draft｜剧本模式第二页**

## 任务输入

用户故事或图片起点、目标片长、创作要求、已经决定的人物与限制，以及本次是全新起草还是接续/更新指定范围。图片仅在实际发送且模型支持时作为视觉输入；否则明确是文字描述。

## 给模型的任务草案

```text
根据本次创作意图，写出当前范围内可直接阅读和编辑的影视剧本。用画面、动作、声音、对白和必要的停顿使故事发生，而不是交付主题说明或拍摄提纲。

目标时长是节奏约束，不是正文后附一个分钟数。内容量需要由可发生的动作、对白、停顿与场景变化支撑；时长只能合理估计，不声称已经精确测定。

先让故事及其视听表达成立，不按视频模型单次时长提前切块。不要求每一段填满机位、天气、焦距等属性。按用户的文风和表达方式写作，允许作品保留必要的沉默、留白或非直白关系；不要额外解释寓意。

全新起草可在用户允许范围内发展情节。更新已有文本时，以当前正文为基础，只改本次允许范围，不因再次起草就丢弃用户手工修改。

将正文组织为轻量 blocks，每块仅承载自然段落或场景阅读单位，不把它们当正式分镜或生成片段。不要同时返回一份重复而可能不同的 full_text。
```

## 建议 payload

`title`、有序 `blocks`、可选 `duration_estimate_seconds`。每个 block 可包含 `ref`、`heading`、`text`；既有范围使用提供的 ref，新内容用临时 ref。时长估计不确定时可为 null，不能用数字掩盖内容不足。

## 用户看到什么

第二页显示标题与按顺序阅读的自然语言正文；可比较和编辑。段落标识、机器协议不显示为写作内容。默认不附“创作思路”段落。

## 长文边界

一次响应容量不足，应由网站在请求前提出分批范围。每批模板仍交付当前范围完整正文；整部任务未完成时，网站显示“部分完成”。不得让模型用摘要替代后半篇，或伪称整部剧本已经交付。

各批候选分别绑定所依据的正文版本，用户可明确应用已完成范围。后批若使用前批新内容，应说明那是本次候选依据，不冒称用户已确认。不同回答中的临时 ref 由网站分别映射，不能重复追加或串成同一块。局部用户修改使后批依据变化时，先保留成果再核对，不重新从头生成覆盖已写部分。

## 继续打磨的问题

自然段落的粒度、目标时长提示怎样不干扰阅读、分批结果何时允许局部应用，归入 Q11。不要先把全站剧本写作变成严格的影视字段表。
