# 分镜创作模板

> V2.9：本文件为可读设计说明。未来运行读取 `运行模板/` 的对应纯TXT，任务/Schema/正文取值以 `配套清单/llm-task-registry.json` 为准；原“字段未定”说明不覆盖新合同。未进行模型实测。

**任务：storyboard｜剧本模式第四页**

## 输入

当前资产版范围、已经形成的分镜及用户修改、有效资产和视觉意图、节奏要求、本次允许新增或改写的范围。

## 给模型的任务草案

```text
把当前剧本范围组织为有叙事和视听目的的分镜。每个分镜承载完整画面、动作或剧情意图，说明观众在这一镜中看见什么、听见什么、变化怎样发生。

分镜不是一次视频模型请求。不要为了适应单次时长把完整意图提前切碎，也不要把整部作品只写成镜头编号和几个标签。

以自然语言落实必要的景别、视角、站位、动作、对白、声音及镜头意图。不要求每一镜重复所有资产属性，不为填写字段补造故事中没有的事件。

已有分镜的局部修改遵守当前范围，保留其他分镜及确认事实。对需要更多创作决定的关联，放在问题或说明中，不直接改写上游。

返回分镜候选与来源对应，不返回视频参数、素材路径、工作流节点或已生成结果。
```

## 建议 payload

`shots` 有序列表，每项包含 `ref`、`title`、`source_refs`、`text` 与可选 `duration_hint_seconds`。文本为核心，来源与时长为辅助结构。

网站将结果应用为正式对象后，分配稳定身份。左侧轴显示分镜，候选比较留在中间，不把每次模型尝试新增成一个分镜节点。

## 片段尚不存在时

分镜可以先成立，再在第五页拆成生成片段。此任务不伪造子片段来填满左轴；也不偷偷连带写正式 H3 Prompt。

## 继续打磨

分镜标题长短、来源段落折叠方式及分镜全文阅读方式，可结合用户真实作品比较。它们不改变“自然语言分镜与单次生成片段不同”的边界。
