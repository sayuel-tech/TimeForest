# 上下文摘要与格式修复

> V2.9：本文件为可读设计说明。未来运行读取 `运行模板/` 的对应纯TXT，任务/Schema/正文取值以 `配套清单/llm-task-registry.json` 为准；原“字段未定”说明不覆盖新合同。未进行模型实测。

**两种独立辅助任务｜不应合并调用，也不成为每次写作的必经步骤**

## 一、上下文摘要

任务类型为 `context_summary`。输入是网站选定的正文范围、相关事实、待处理的局部任务和来源标识。

### 给模型的任务草案

```text
为后续指定创作任务整理相关上下文。保留会影响当前人物关系、知情状态、时序、服装/物件连续性和表达意图的事实，以及尚未解答的问题。

摘要用于读取，不替代正式剧本。保留原作的未定和留白，不把开放问题写成已经有答案，不为故事添加主题判断或新的因果解释。

仅概括提供的范围，并指明依据。当前任务不需要的历史细节可以省略，但不能把会改变下一段理解的关键事实删掉。

返回 summary_text 与 source_refs，不重写正文，不宣布摘要已经确认。
```

摘要缓存依赖来源版本与任务用途。上游改变后，网站判断是否需要更新；不长期用旧摘要覆盖新事实。不要求每个局部改写都额外调用一次摘要模型。

长文分批时，摘要只帮助传递必要关系，不替代各批正式正文。未确认候选与用户确认事实应分开传递；不能为了缩短上下文把尚未决定的剧情压缩成既定事实。

## 二、格式修复

格式修复沿用原任务的 task_type 和输出约定，不新建一份“修复后剧本”的内容层。输入仅包含完整原始回答、结构错误说明及原返回约定。

### 给模型的修复约定草案

```text
本次只修复原始回答的表示形式，使它符合所给返回约定。保留可恢复的创作内容，不润色、不缩写、不补剧情，不改变角色、对白、引用或秒数。

可以移除对象外聊天包装，修正确定的序列化错误，将已有说明放回正确位置。不要为了满足结构而发明缺失事实。

原内容无法完整恢复时，不伪装修复成功。按原约定报告需要重新请求；不要把推测补齐的文字混入正文。

只返回原任务约定的对象，不解释修复过程。
```

这段不是保证可靠修复的技术证明。网站仍需检查内容差异；无法判断是否改动时，保留原回答和修复候选供比较，不能自动应用。

### 不适合修复的情形

模型回答因长度上限被截断、网络中断未取得全文、实际素材或能力缺失，这些不是简单 JSON 语法错误。它们应当缩小任务、明确续写或补资料，不能通过“修复格式”偷偷触发另一轮创作。

建议默认用户触发、至多一次修复。重复失败保留原因，不循环计费。供应商拒答或服务错误不伪装成普通创作成功。
