# 资产完整版模板

> V2.9：本文件为可读设计说明。未来运行读取 `运行模板/` 的对应纯TXT，任务/Schema/正文取值以 `配套清单/llm-task-registry.json` 为准；原“字段未定”说明不覆盖新合同。未进行模型实测。

**任务：asset_screenplay｜剧本模式第三页**

## 输入

原剧本的相关确认内容、当前资产完整版、用户手工修改、已确认绑定与用途、项目内覆盖、本轮绑定差异，以及实际提供的图像或带来源的观察。

## 给模型的任务草案

```text
将本轮已经确认的资产选择落实到当前范围的自然语言剧本。不是重新发明故事，也不是把每张资产的全部资料粘贴进每个镜头。

首次整理以确认剧本为基础。更新已有资产版时，以当前资产版和用户修改为基础，只处理本轮变化及直接相关描述；不要每次从最初剧本重新生成全部内容。

分别理解人物身份、服装状态、声音和场景用途。换服装参考不等于换剧情人物，风格图也不等于场景内必须出现图中的全部物体。

明确剧情事实与绑定资料冲突时，不自作决定。例如剧情要求红衣，而绑定图显示灰衣，应说明冲突，由用户确定使用方式。未提供的图片细节不能当成观察事实。

输出当前约定范围的完整资产版正文。只将正文放入 blocks；变化摘要和必要冲突分别放到外层说明或问题区，不写进正式剧情。
```

## 建议 payload

`blocks`，每块包含既有 `ref`、`heading`、`text`；可选时长估计仍是创作估计。只有任务明确允许时才新增临时块，不能因补充外貌擅自重组整篇身份对应。

## 冲突与部分成果

可选描写不明确时可以保留原文并说明局限。冲突涉及本次必须落实的核心设定且未有用户选择时，建议 needs_input、payload 为 null；旧资产版保持不变。

网站保存绑定成功但本任务失败，仍保留绑定和旧正文，标注待更新。成功回答也只产生候选，不宣布分镜、片段和电影已同步。
